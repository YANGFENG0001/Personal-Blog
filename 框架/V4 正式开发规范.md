# FIELDNOTES / AI Learning Garden — V4 内容工作台与模块化正式开发规范

> 2026-10-10，基于此前已确定的 V3 需求（左侧悬浮分站轮盘、顶部仅展示分站栏目、公开页面无登录入口、独立站主管理页面、可选公开指标、概率递增鼓励弹窗、DIY）。本文件是 **增量修改 + 新增功能的权威说明**。附带的 HTML 原型是交互示范，**不是安全生产系统**。

## 0. 定位与非目标

公开部分为中文专业独立博客、AI 研究笔记与资源平台。站主私人区域为内容工作台（写作、整理、成长足迹、任务和知识库）；**站主私人进度、待办、草稿、未公开文章与设置不得传输给访客**。不要将其做成卡通打卡 App，不要在公开首页强制摆放成就卡片。

## 1. 分离的入口与权限

- 游客：`/`，可通过左侧轮盘切换整站（学习、研究、技术、日常、资源及站主自定义分站），各分站上方出现本分站栏目。游客顶部不出现登录入口。
- 站主：`/owner` 或独立私有子域，进入后有私人总览、编辑器、文章库、知识库、日程待办、分站栏目、展示权限、彩蛋时间与外观 DIY。独立登录；“记住登录”只用于持久安全会话而非保存明文密码。
- 管理区右下角悬浮球切换到**游客可见的实时预览**，再次点击返回工作台。游客普通页面永不出现悬浮的管理切换球。
- **权限在服务端查询和构建层执行**；访问未公开文章返回 404/403；私人笔记内容、摘要、图片、Markdown 源文件、搜索索引、RSS、sitemap、静态 JS 和 JSON 均不可公开泄漏。

## 2. 文章写作与发布：P0

### 操作闭环

从“总览快捷写作”“文章库编辑”“知识库栏目新增”进入统一编辑器。支持：

1. 新建 / 编辑 / 保存草稿 / 预览 / 发布 / 更新发布 / 撤回公开（改为草稿或取消公开权限）。
2. 文章标题、摘要、站点、栏目、标签、日期、置顶/精选（按需）、正文 Markdown。
3. **简单起步模板**：论文精读、技术博客、学习笔记、研究心得、自由文章。模板仅填初始字段，不锁死写作方式；切换模板须确认是否覆盖已有修改。
4. **进度状态**（可留空）：待读 / 阅读中 / 已精读 / 复现中 / 进行中 / 已完成；在站主管理与公开文章详情按独立的展示规则呈现。可日后让站主自定义词库。
5. **我的心得/反思**（可选多行文本）：独立于 Markdown 正文，支持缺省；可在公开文章中按该文章公开策略渲染（增加独立“心得是否公开”开关更佳）。若文章为私人内容，该字段绝不公开。
6. **相关链接**（0..N）：`label` 与 `url`，支持新增、删除、重排；只接受 `https://`/`http://` 协议，持久化时服务端验证并进行 XSS 净化。访客打开公开文章时：如果有非空且有效的相关链接，**右侧原本的通用侧栏用相关链接模块整体替换**；没有链接则保留原先的侧栏，不出现空盒子。手机端相关链接在正文之后自然排列。
7. 导入 `.md` / `.markdown` 文件：文本读取、UTF-8、限制上传大小、解析 YAML frontmatter（如标题、标签、日期可选择导入映射），确认后进入编辑器而**非直接发布**；文件名/标题建议，错误提示；正式版还需校验路径与资源引用。
8. 技术内容至少支持 Markdown、代码高亮、LaTeX 公式、引用块、表格、目录、锚点、图片和安全外链。预览与生产渲染尽量使用同一管线，避免样式偏差。
9. 应支持草稿 / 私人 / 已发布状态。`publish` 不等于 `visibility=true`：公开取决于文章已发布 ∧ 文章允许公开 ∧ 分站允许公开 ∧ 栏目允许公开；若模块有单独权限，再与模块权限做 AND。

### 推荐数据模型（最小集合）

```ts
type Post = {
  id: string;
  slug: string;
  title: string;
  summary?: string;
  siteId: string;
  categoryId: string;
  tags: string[];
  status: 'draft' | 'published' | 'archived';
  visibility: 'private' | 'public';
  templateId?: 'paper'|'tech'|'learning'|'reflection'|'free';
  progress?: string;
  bodyMarkdown: string;
  reflectionMarkdown?: string;
  links: Array<{id:string; label:string; url:string; order:number}>;
  featured?: boolean;
  createdAt: string; updatedAt: string; publishedAt?: string;
};
```

发布接口必须校验分站与栏目归属。`publishedAt` 应记录首次发布时间（或者明确采用最近一次发布时间）。编辑原有文章不可意外改变 slug 导致旧链接失效；删除分站/栏目前检查子内容或迁移。

## 3. 站主“成长足迹”和“知识库”：P0/P1

私人首页展示计数和趋势（文章总数、已发布、独立发布天数、连续发布天数、论文精读记录、学习里程碑/连续学习数据等）。

- 默认**仅站主可看**；公开面板统一经过站主显式开启的指标白名单。绝对不能把私有条目统计细节嵌入公众 HTML。
- “建站天数”按站主设定时间计算；“连续在线”来自可信 uptime 监测而非自填真实值；“文章发布天数/连续天数”以真正已公开文章日期去重计算；“连续学习”来自私有学习记录。
- 知识库：按分站→栏目→文章组织，支持新增文章、编辑、状态、检索，未来扩展双向引用、关联论文、知识图谱。
- 文章模板中的“论文精读”并不要求任务模块名称叫“论文精读”，两者独立。

## 4. 任意 DIY 的待办/日程模块：P0

站主私有任务板可新增、重命名、删除、排序，例如 `论文精读`、`技术实践`、`本周计划`、`日常日程`，或完全自定义；每个任务板有任意数量任务。

任务数据：`id, boardId, title, note?, priority?, dueDate?, status, completedAt?, order`。操作：新增 / 编辑 / 完成 / 取消完成 / 删除；P1 增加拖拽排序、重复日程、提醒、截止日期筛选以及关联文章/论文。模块通过注册表控制启用和显示顺序，不依赖固定名称。任务板默认私有，若未来做公开任务表，需要独立的明确许可模型。

## 5. 全站 DIY 模块架构

保持 V3 模块开关和交互，新增**站主仪表盘模块注册表**与文章编辑模块注册表：

```ts
type SiteModule = {
  id: string;
  name: string;
  zone: 'public-home'|'public-sidebar'|'public-article'|'owner-dashboard'|'owner-editor';
  enabled: boolean;
  visibleTo: 'public'|'owner';
  order: number;
  settings: Record<string, unknown>;
};
```

站主可以新增/删减/排序模块，关闭可选模块，设置配色、字体、密度、动画强度和文案；**基础权限检查、登录安全、文章渲染安全不能被 DIY 关闭**。外观 DIY 不得影响文章数据模型与发布权限。数据字段可按 schema 版本迁移。

## 6. 技术实现建议（须明确不再是纯静态后台）

此前的 Astro + Starlight + starlight-blog 继续保留为**公开内容展示层**，但现在新增在线站主管理、可即时编辑发布与私密任务：只有 Git 驱动的纯静态站无法满足。需要增加受保护的应用/API 层。

一种合理组合：
- 公开渲染：Astro + Starlight 与 Astro 自定义页面，保留简洁博客主题。Starlight 部分承担学习知识库。
- 管理界面：Astro 页面或隔离的前端应用；表单验证 Zod。
- 认证：成熟身份服务或服务端 session（Secure + HttpOnly + SameSite），CSRF 防护，强身份鉴权与限速。不要使用 localStorage 密码或前端 `isOwner` 来保护私有内容。
- 内容数据库：SQLite/D1、PostgreSQL 或适当的受保护内容存储；草稿/任务/私有日志不参与游客静态打包。可把正式发布内容同步/导出为 Markdown + Git，以方便备份和长期迁移。
- 附件与 Markdown 上传：独立受限文件存储，MIME/大小/路径/内容安全验证，避免任意文件执行、HTML 注入与 SSRF。
- 若全站采用纯静态构建：发布要触发受控构建流程，并解释发布延迟；若需立即生效：采用 SSR/边缘渲染/API 内容拉取。不能同时承诺完全静态与即时生效且不提供发布流水线。

## 7. 验收测试（必须自动化）

- 新建四种模板文章；编辑标题、MD 正文、状态、心得、多条链接，保存草稿后游客不存在；发布后游客可查看；撤回后游客不可访问。
- 导入有效 `.md` 自动填写编辑器，不会擅自发布；非法格式与大文件友好提示。
- 有相关链接文章的右侧显示相关链接并**替换**作者/统计/Colophon 侧栏；无链接正常显示原侧栏；手机适配。
- 分站、栏目、文章任意关闭均立即从游客导航、列表、文章直链、搜索、RSS、sitemap 消失（按发布策略保证最终一致性）。
- 站主私人增长数据、知识记录、任务与草稿从所有公开资源（HTML/JS/JSON/API）完全不可获取。站主管理修改私人任务或复选状态会持久保存。
- DIY 新建任务板“论文精读”，重命名为“模型复现”，新建任务、完成、取消完成、删除均正常；关闭工作台任务模块不丢数据。
- 公开页面无登录按钮；站主可通过私有入口登录（有效会话免重新登录），切换游客预览和返回。
- 动画遵循 `prefers-reduced-motion`，键盘可用；针对 XSS、越权、IDOR、CSRF、Markdown 链接协议、文件上传与重放进行检查。

## 8. 开发实施顺序

1. 建立真实后端与认证、数据模型/迁移、分站栏目权限；保留 V3 公开网站设计。
2. 实现基础文章 CRUD、草稿→预览→发布→撤回，接入真实 Markdown 渲染。
3. 实现文章模板、进度、心得、相关链接替换、MD 导入。
4. 实现站主仪表盘、知识库、DIY 任务板和统计数据。
5. 实现跨模块配置、主题、权限与随机鼓励；移动端与可访问性优化。
6. 自动化验收并部署、备份与恢复说明。任何阶段都必须可启动、可测试，不写只有展示效果的空按钮。

## 9. 原型的已知边界

V4 原型只有 HTML/CSS/JavaScript，浏览器 localStorage 保存帖子和任务，演示登录接受任意非空口令，Markdown 仅支持基础语法。**演示站不能部署成真实含私密内容的站主应用**。原型跨两个入口共享数据通常需要在同一 HTTP(S) origin 下提供 `index.html` 和 `owner.html`，独立 file:// 打开是否共享存储取决于浏览器。原型无真实 Markdown 编译、稳定跨设备同步或服务端发布。请按以上约束落地正式应用。
