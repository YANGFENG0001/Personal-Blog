# 个人博客与 AI 学习研究平台——完整项目开发需求书

## 一、项目背景与开发目标

我希望开发一个长期使用、完全自主控制、设计精致的个人网站系统。

这个网站不仅是一个传统意义上的博客，同时也是我个人的学习空间、人工智能研究记录平台、技术知识库、个人生活记录平台，以及可自由扩展的个人信息管理系统。

**整个系统分为两个相互关联但权限独立的部分：**

1. **公开网站（游客端）**：用于展示我主动选择公开的文章、研究成果、技术博客、学习记录、资源和其他内容。
2. **站主工作台（管理端）**：用于内容编辑、文章发布、知识整理、学习进度、成长记录、日程管理、网站配置以及其他私人用途。

最核心的原则：

**公开网站展示什么，必须完全由我作为站主决定。**

我可以选择公开哪些分站、栏目、文章、个人信息和统计数据，也可以将某些内容完全保留在自己的私人工作台中。

我提供的 V4 原型 ZIP 和开发规范只是此前讨论中生成的初步草稿，并不是最终设计或最终架构。

请你仔细检查并理解这些文件，但不要被原型的代码结构、功能实现、视觉细节或技术缺陷限制。

你需要在保留我核心需求的基础上，主动审查、优化、重构并开发一个能够长期使用、可维护、可扩展、安全且具有专业设计品质的正式项目。

## 二、整体设计风格

### 2.1 设计定位

网站必须体现成熟、简洁、专业的个人技术博客与独立研究者网站的感觉。

我不喜欢过于卡通化、过度装饰、模板化、明显带有 AI 自动生成痕迹的网页设计。

希望整体具有以下特征：

- 专业博客和独立研究者网站的气质
- 现代、极简、优雅、有品质的排版
- 中文阅读体验优秀
- 适当的留白和清晰的内容层次
- 有设计感但不浮夸
- 细腻、自然、克制的动态效果
- 适合长篇论文、技术博客、代码和数学公式阅读
- 支持日间模式和夜间模式
- 支持移动设备和平板电脑
- 视觉风格具有统一性，但允许不同分站适度个性化

不要大量使用无意义的渐变色、卡通插画、巨大圆角卡片、夸张的数据仪表盘或装饰性图标。

网站的主要价值应体现在内容、阅读体验和精致的细节交互上。

### 2.2 动效要求

我希望网站具有精致且富有设计感的交互体验，但不能因为动画影响性能、阅读或操作效率。

例如：

- 页面进入和离开时的自然过渡
- 分站切换时的全局转场
- 侧边分站选择器的展开与收起
- 文章和栏目切换时的轻量动画
- 头像悬浮简介
- 按钮和菜单的细微交互反馈
- 站主模式与游客预览模式的切换
- 随机彩蛋和鼓励提示出现时的特殊动画

上述效果应支持自定义、关闭或调整强度。

同时尊重用户设备的减少动态效果设置，避免频繁、强烈或令人疲劳的动画。

## 三、整个网站的多分站系统

这是我非常重视的一项设计。

### 3.1 分站概念

我希望网站不是一个单层博客，而是由多个主题明确的分站组成。

初始可以设置以下分站：

- 学习
- 研究
- 技术
- 日常
- 资源

这些只是初始内容，站主可以自行增加、删除、修改、隐藏、排序和配置分站。

每个分站都相当于网站内部一个相对独立的内容空间。

例如：

**学习分站**

用于 AI 基础知识、学习笔记、课程记录、知识体系等。

**研究分站**

用于论文精读、研究心得、论文复现、实验记录等。

**技术分站**

用于编程技术博客、技术实践、工程项目、开发经验等。

**日常分站**

用于个人文章、生活随笔、阅读记录、日常思考等。

**资源分站**

用于工具推荐、资料整理、论文资源、技术链接等。

未来如果需要新增其他领域，也应该可以直接通过后台完成。

### 3.2 分站切换方式

**不要把所有分站横向排列在网页顶部导航栏。**

我希望采用网页左侧一个精致、小巧的隐藏式分站切换控制器。

设计要求：

1. 默认收起，页面左侧只露出一小部分具有设计感的控制器。
2. 鼠标移入时自然展开。
3. 整体形态可以是小型轮盘、弧形菜单或其他经过设计的精致交互形式。
4. 鼠标移出后自然收回。
5. 不能长期占据过大的屏幕空间。
6. 切换分站时，通过流畅的全局过渡动画切换对应页面及内容。
7. 可以选择不同的轮盘样式、展开效果和切换动效。
8. 移动端必须提供符合触摸操作习惯的替代交互方式。
9. 支持键盘操作，不能依赖鼠标悬停才能使用。

**整个网站的分站切换主要通过该控制器完成。**

不需要额外在右侧设置重复的分站索引。

### 3.3 每个分站内部的栏目

切换到一个分站之后，网页顶部才显示该分站对应的栏目导航。

例如进入研究分站，顶部可以显示：

论文精读 / 研究心得 / 实验记录 / 研究项目

进入技术分站，顶部可以显示：

技术博客 / 技术实践 / 项目开发 / 技术总结

每个分站的栏目必须可以独立配置。

允许站主：

- 新增栏目
- 删除栏目
- 修改栏目名称
- 调整排列顺序
- 配置栏目简介
- 控制栏目是否公开
- 为栏目选择展示形式
- 管理栏目下的文章
- 自定义栏目内容模块

分站及栏目应作为真正的数据模型实现，而不是简单写死的页面。

## 四、公开网站的展示控制

### 4.1 完全由站主决定展示内容

站主应该可以通过管理后台，控制：

- 哪些分站公开
- 哪些栏目公开
- 哪些文章公开
- 哪些个人信息公开
- 哪些学习记录公开
- 哪些成长统计公开
- 哪些页面模块公开
- 哪些功能对游客启用

建议采用清晰的可见性设置，例如：

- 公开
- 私有
- 草稿
- 定时发布（如果实现）

对于文章，发布状态与可见性应合理区分。

例如，我可以把某篇论文精读保存为草稿，也可以完成后仅供自己阅读，或者正式公开发布。

不能因为一篇文章已经在站主端保存，就自动对外可见。

### 4.2 隐私保护要求

私有内容不能只是使用 CSS 隐藏或者在前端 JavaScript 中过滤。

未授权用户必须无法通过网页源码、公开接口、静态文件路径、搜索结果、RSS、站点地图或其他方式读取私人内容。

这包括：

- 私人文章
- 私人论文笔记
- 未公开学习进度
- 私人日程
- 私人任务
- 未发布内容
- 其他仅供站主使用的数据

访客只应接触到明确允许公开的内容。

## 五、站主个人信息与头像

网站应该有一个小巧、美观的站长头像。

当游客把鼠标悬浮在头像上时，弹出精致的简介卡片。

简介卡片可以包含：

- 个人昵称
- 一段简短介绍
- 研究或技术兴趣
- GitHub 等社交链接
- 可选的个人网站信息

头像、简介和相关链接应能通过后台修改。

简介内容以及是否公开都可以单独配置。

移动端可以通过点击头像查看简介。

不要把头像做成夸张的装饰，也不要让它影响正文阅读。

## 六、文章编辑、管理与发布系统

站主管理端必须提供真正可用的内容管理功能。

### 6.1 文章基本操作

至少支持：

- 新建文章
- 编辑文章
- 保存草稿
- 发布文章
- 修改已发布文章
- 撤回公开文章
- 删除文章
- 预览文章
- 搜索文章
- 按分站、栏目、标签、状态筛选
- 设置文章所属分站和栏目
- 管理文章标题、摘要、封面、标签、发布日期等元信息

必须实现实际的数据保存与持久化，不允许仅作为界面演示。

### 6.2 Markdown 编辑

我希望以 Markdown 为主要内容格式。

要求：

- Markdown 编辑与预览
- 支持导入 `.md` 文件
- 支持代码块和语法高亮
- 支持数学公式
- 支持图片
- 支持标题和目录
- 支持引用、表格、链接等常见语法
- 尽量支持本地图片或附件的规范化导入
- 保存后能够重新打开并编辑
- 预览效果尽可能与公开文章阅读页面一致

可以增加方便写作的编辑器工具栏，但不要牺牲 Markdown 的可迁移性。

### 6.3 文章模板

编辑器需要提供几种简单实用的内容模板。

初始模板可以包含：

**论文精读模板**

包含论文信息、研究背景、核心问题、主要贡献、方法理解、重要公式、实验结果、个人心得、相关资料和复现情况。

**技术博客模板**

包含背景、问题分析、解决思路、代码实现、结果、总结和参考资料。

**学习笔记模板**

包含学习主题、核心概念、知识梳理、疑问和个人总结。

**研究心得模板**

包含研究主题、思考过程、观点、问题和后续方向。

**自由文章模板**

不限制文章结构，适合随笔、日常记录和其他类型的内容。

模板的作用是帮助快速开始写作，而不是强制规定文章格式。

模板应该可以在管理后台进行添加、编辑、删除和调整。

### 6.4 文章进度状态

编辑文章时，可以设置当前内容或研究任务的进度状态。

例如：

- 待读
- 阅读中
- 已精读
- 计划中
- 进行中
- 复现中
- 已完成
- 暂停

状态可以根据文章类型显示不同选项，并允许站主自行扩展。

进度状态是否对外展示也应该可以配置。

### 6.5 心得记录

编辑器中应有一个独立的心得或个人思考区域。

例如：

- 阅读感想
- 技术理解
- 论文思考
- 实验体会
- 尚未解决的问题

这些内容可以是文章的一部分，也可以根据需要作为独立字段管理。

是否公开应由站主决定，私人心得不能因为文章公开就必然公开。

### 6.6 文章相关链接

编辑文章时，我可以添加多条相关链接。

例如：

- arXiv 论文
- 论文原文
- GitHub 代码仓库
- 项目主页
- 官方技术文档
- 参考博客
- 数据集
- 其他资源

每个链接至少支持链接名称、URL，最好还支持分类和排序。

**公开文章页面需要实现以下特定交互：**

如果一篇公开文章配置了允许公开的相关链接，则在文章页面右侧靠下的位置显示一个精致的相关资料区域，用于替换原本默认显示的侧栏内容。

如果文章没有配置相关链接，则仍然显示原本的默认侧栏布局。

不要因为没有相关链接就留下突兀的大块空白。

移动端应将相关链接区域调整为合适的位置。

链接需要正确处理安全性和失效情况。

## 七、AI 学习与论文研究功能

网站最初的重要用途之一，就是帮助我系统学习人工智能。

### 7.1 AI 知识库

应该支持整理：

- 机器学习
- 深度学习
- PyTorch
- Transformer
- 大语言模型
- RAG
- AI Agent
- 模型训练与微调
- 其他自行创建的知识方向

知识内容可以按层级组织，方便查阅和长期维护。

允许我不断添加文章、知识节点、相关链接和分类。

知识库既可以作为公开分站栏目，也可以在站主私人工作台中独立管理。

私人知识内容不应自动同步到游客可访问的网站。

### 7.2 论文阅读

希望论文内容能记录：

- 论文标题
- 作者
- 发布年份
- 原文链接
- 研究方向
- 阅读状态
- 论文摘要
- 核心贡献
- 方法理解
- 重要公式
- 实验分析
- 个人心得
- 相关代码
- 是否完成复现

这部分与文章编辑器共享基础能力，但可以提供更适合论文研究的编辑模板和管理方式。

## 八、私人工作台、成长足迹与知识整理

站主管理界面不仅是网站设置后台，也应该是可以长期使用的个人工作空间。

### 8.1 私人首页

可以展示：

- 最近编辑的文章
- 尚未完成的论文阅读
- 正在进行的技术实践
- 私人学习统计
- 最近的学习记录
- 待办事项
- 近期成果
- 自定义模块

这些内容默认只对站主可见。

### 8.2 成长足迹与成就

我需要记录个人学习、研究和技术实践的进展，并获得一定的成就感。

例如：

- 阅读论文数量
- 完成精读的论文数量
- 技术实践数量
- 文章发布数量
- 学习进度
- 学习阶段里程碑
- 已完成任务
- 个人成就记录

但我不希望把这些打卡、成就或私人进度默认展示给游客。

**成长系统首先为站主自己服务，对外展示只是可选功能。**

### 8.3 自定义私人任务模块

管理界面需要有可 DIY 的日程、任务和待办模块。

不要将所有任务固定为一种通用待办事项。

我希望可以创建不同的任务板，例如：

- 论文精读
- 技术实践
- 学习计划
- 研究项目
- 日常待办
- 其他个人创建的类型

每个模块支持：

- 创建
- 修改名称
- 删除
- 调整顺序
- 增加任务
- 编辑任务
- 标记完成状态
- 可选的截止日期
- 可选的备注及关联文章
- 选择是否展示在私人首页

希望未来可以方便地扩展更多字段和展示方式。

## 九、时间统计与连续记录展示

这是需要做成可配置模块的功能。

我希望网站可以选择展示以下数据：

1. 网站上线天数
2. 连续在线天数或其他可配置的连续记录天数
3. 有文章发布的累计天数
4. 连续发布文章天数
5. 连续学习天数
6. 其他自行添加的时间或成长统计

这些指标必须能够单独开启和关闭。

例如：

我可以只公开网站上线天数，不公开任何学习打卡信息。

也可以在某个分站公开连续学习天数，在其他分站完全隐藏。

站主需要可以设置：

- 是否启用统计
- 是否对游客公开
- 统计起始日期
- 统计名称
- 统计的计算规则
- 统计模块的展示位置
- 统计模块的样式

具体的数据含义应清晰定义。

例如“累计发布天数”应该按照实际有文章公开发布的日期计算，而不是简单使用文章篇数代替。

“连续在线天数”如果要代表真实服务可用性，需要可靠的在线监测数据，不能只按照建站日期伪造。

这些统计不必始终在首页出现，可以作为小型信息模块展示在适合的位置。

## 十、随机彩蛋与鼓励系统

我希望网站具有一些克制、精致、有温度的小彩蛋。

### 10.1 随机小彩蛋

可以在网站不同位置设计一些小型随机交互。

例如：

- 特定操作触发小动画
- 特殊文字提示
- 精致的节日或时间彩蛋
- 随机的轻量视觉效果
- 某些隐藏的设计细节

这些彩蛋不应影响正文阅读、网页操作或网站性能。

站主可以控制是否开启。

### 10.2 随机鼓励提示

这是一项我希望重点实现的功能。

网站可以按照用户停留的时长，随机出现一些优美的鼓励提示。

**提示内容的表现形式：**

首先展示一句有感染力或启发意义的话，例如：

- 名人名言
- 经典格言
- 动漫作品中的经典台词
- 具有代表性的经典发言
- 其他经整理的短句

再通过自然的文字过渡，引出一段鼓励用户学习、思考或继续探索的话。

提示应该具有美感，避免机械、俗套、过分鸡汤的表达。

引用需要尊重版权与来源，不要伪造名人或作品出处。

### 10.3 概率触发机制

希望采用可配置的概率增长机制。

例如：

每隔五分钟进行一次随机判断。

初始触发概率为 a。

如果没有触发，下一轮概率可以按照站主设置的规则逐渐增加。

累积到站主设定的最高概率后，不再继续提高。

站主应能够设置：

- 是否启用
- 判断时间间隔（默认五分钟）
- 初始概率 a
- 每轮增加多少概率
- 最大概率上限
- 提示展示持续时间
- 提示动画效果
- 提示文案库
- 冷却时间
- 是否在文章阅读或编辑时减少干扰

## 十一、独立站主管理入口与身份认证

### 11.1 游客页面

**公开网站不要保留任何明显的“站长登录”按钮或后台入口。**

该页面应具有真正的身份验证机制。

### 11.3 自动免登录

希望支持安全的长期登录体验。

例如：

- 首次验证身份后保持登录
- 在合理期限内无需频繁重新登录
- 支持主动退出
- 会话过期重新验证
- 支持后续扩展更安全的认证方式

不允许将密码明文保存到浏览器中，也不允许使用前端硬编码口令作为正式认证。

### 11.4 站主与游客视角切换

进入站主后台后，希望有一个精致的小型悬浮球。

点击可以切换到游客实际能看到的网站。

在游客预览模式下，再点击该悬浮球，可以返回站主工作台。

悬浮球应该有细腻的动画效果，并且可以调整位置或开启关闭。

注意：

这个悬浮球是**已经认证的站主专用操作入口**，普通游客不应看到，也不能借此进入后台。

切换到游客预览时，必须按照真正的公开权限渲染内容，不能显示私人数据。
