# 主题制作（通用）

主题不是「换几个颜色」，是**一套受约束的视觉决策**。本技能给的是判断顺序和验收标准，不是配色表。

## 0. 顺序不能颠倒

```
可读性 → 层次 → 情绪 → 装饰
```

先保证正文读得下去，再谈好不好看。绝大多数「主题很丑」的真实原因是**正文对比度不够、背景抢戏**，不是配色品味问题。

## 1. 可读性是硬约束，不是建议

### 1.1 对比度下限

| 用途 | 对比度（WCAG） | 说明 |
|---|---|---|
| 正文 ink / 页面底色 bg | **≥ 7** | AAA。低于 4.5 直接不可用 |
| 次级文字 muted / bg | ≥ 4.5 | AA |
| 辅助文字 faint / 卡片底色 surface | ≥ 4.5 | 最容易翻车的一项 |
| 强调色 accent / bg | ≥ 3 | 用于链接、按钮边框 |
| 按钮文字 / accent 底 | ≥ 4.5 | 反色也要算 |

用脚本一次算完，别靠眼睛：

```bash
node scripts/contrast-check.mjs palette.json
```

`palette.json` 形如 `{ "light": { "bg": "#fbf7f9", "ink": "#2a2433", ... }, "dark": { ... } }`，脚本会按上表逐项判定并给出修正建议。

### 1.2 夜间不是「把日间调暗」

- 夜间底色不要用纯黑 `#000`，用 `#0f1424` ~ `#171a2e` 这类带色相的黑，眼睛舒服得多。
- **夜间的 accent 要比日间更亮、更浅**。直接照抄日间颜色，在深底上会糊成一团。
- 夜间正文不要用纯白 `#fff`，用 `#e8eaf8` 这类微偏色的白，减少光晕。

### 1.3 背景上的文字

有图片或场景背景时，正文区必须加**阅读底板**（半透明 surface + 模糊）：

- 底板不透明度 ≥ 0.85（图片背景）/ ≥ 0.6（纯色渐变背景）
- 或者把视觉主体放到右侧/底部，**左侧约 60% 保持低对比、少细节**

这条比配色更影响观感。背景再美，正文读不下去就是失败的。

## 2. 配色体系

### 2.1 九色制

一套主题通常需要九个语义色，而不是一堆色值：

| 键 | 语义 | 注意 |
|---|---|---|
| `bg` | 页面底色 | 日间偏暖白/冷白，夜间带色相的黑 |
| `surface` | 卡片、浮层 | 与 bg 差 2–4% 明度即可，别差太多 |
| `ink` | 正文 | 对比度 ≥ 7 |
| `muted` | 次级文字 | ≥ 4.5 |
| `faint` | 辅助/占位 | ≥ 4.5（对 surface） |
| `line` | 分割线、边框 | 只要「看得见」，别太重 |
| `pane` | 内嵌区域 | 比 surface 再深/浅一档 |
| `accent` | 强调 | 全套里唯一高饱和色 |
| `tint` | 强调色的极淡底 | accent 的 8–12% 混白 |

### 2.2 只允许一个高饱和色

`accent` 是唯一的高饱和。其余八个色都是**低饱和**。两个以上高饱和色抢注意力，页面会显得廉价。

`tint` 一定是 `accent` 的低透明度版本，不要另起一个色相。

### 2.3 色相锚定

给主题定一个**主色相**（如樱花坂 = 品红 340°、晴空之子 = 蓝 210°、蕾西亚 = 紫 250°），然后：

- `bg` / `surface` / `pane` 带 **2–6% 的主色相**（几乎看不出来，但整套会「像一套」）
- `accent` 落在主色相上或它的邻近色
- 第二色相只用于「夜间 accent 提亮」或极少量点缀

这是「主题不够统一」最常见的原因：每个颜色单独看都对，色相不锚定就散。

## 3. 字体与形状

- **标题与正文用不同字体族**才有层次：`serif` 标题 + `sans` 正文（或反过来）。
- 行高 1.6–2.0；中文正文建议 1.8 以上。
- 字距：标题可微收（-0.01 ~ 0.02em），正文不要动。
- 圆角是一个**情绪参数**：`sharp` 冷静/技术，`soft` 温和，`round` 亲和。整套只用一个档位。
- 密度 `compact / comfortable / spacious` 影响留白，和圆角要匹配（sharp + spacious 会显得空）。

## 4. 背景分层

从下往上最多 4–6 层：

```
1. 底色（纯色或渐变）
2. 远景（天空/城市剪影，低对比）
3. 中景（主体场景）
4. 前景（可透明，轻微视差）
5. 纹理（纸纹/网点/网格，极低不透明度）
```

规则：

- **视差强度 `depth` 只在 0–0.3 之间**。超过 0.4 滚动时会晕。
- 前景层必须透明并且 `pointer-events: none`。
- 纹理层不透明度 ≤ 0.15，否则正文发灰。
- 日间/夜间各出一张，构图相同、只换色温和光源。

### 4.1 一座建筑怎么读作「宏伟森严」

把背景里的塔/纪念碑画得更大不会让它更宏伟，只会让它像一个被放大的道具。真正起作用
的是三个线索：

1. **看不到顶也看不到底。** 顶部淡出、底部出画。淡出要发生在**场景层内部**——如果场景
   层用 `xMidYMax slice` 且只有 46vh 高，把塔顶放到 `topY: -70` 会在白页面上留一条生硬
   的灰带（超出部分不受天空渐变约束）。用 mask 在层内淡出（0→13% 的不透明度爬升）。
2. **模数化结构。** 等距分缝 + 竖向棱线。重复读作秩序，秩序读作森严。分缝间距要整除
   主体高度，否则最后一道缝会挤在边上、暴露"手画的"。
3. **收分（taper）。** 两条侧边向上各收几像素，收拢的两边就是垂直消失点，等价于"相机
   在仰视"。收分量为 0 时它立刻读作一张平面贴纸。

反面约束同样重要：**纪念碑不点灯**。黑色巨构上每一扇亮窗都会把它变回写字楼，因为
"窗"是建筑才有的东西。只留一条竖向发光缝 + 一个核心点。

### 4.2 可读性 veil 会把背景压平，必要时给它开一层"逃生口"

为了正文对比度而在整层上盖半透明白（本项目 45%），会让**所有**明度差消失：`#05060a`
和 `#14171e` 过一遍都变成 `rgb(114,114,118)`。表现是"主体画得再黑也是灰雾"。

这不是调色能解决的，是图层顺序问题：给 veil 一个 `z-index: 1`，把**需要保住明度**的
那一层（本项目 `.sc-mono`，即黑色巨构）提到 `z-index: 2`，城市剪影留在 veil 之下。
这样正文区仍有 veil 保底，主体又能是纯黑。

## 5. 动效与粒子

- 粒子数量 8–30。超过 40 会明显掉帧，且干扰阅读。
- 粒子尺寸 ≤ 24px，不透明度 ≤ 0.7。
- 尊重 `prefers-reduced-motion`：关闭视差、粒子和角色动态。
- 动效只做「持续、缓慢、低幅」的，不做「突然出现」的。

## 6. 与角色联动

主题和看板娘应该是**同一套设定**：配色、场景、角色服装的色相要能对上。切换主题时角色跟着换，比固定一个角色更有整体感。

做法：主题预设里存**角色包的名字**而不是 id（id 通常是内容哈希，重新导入就变），找不到时自动回退到内置角色，删包不会把主题搞坏。

## 7. 验收

- [ ] `contrast-check.mjs` 全部通过
- [ ] 日间/夜间各截一张**含真实正文**的图，肉眼确认能读
- [ ] 背景图上的正文区有阅读底板
- [ ] 滚动时无视差眩晕（`depth` 全部 ≤ 0.3）
- [ ] 窄屏（375px）下背景主体不压正文
- [ ] `prefers-reduced-motion` 下动效关闭
- [ ] 角色在浅色和深色背景下都看得清（深色角色配浅背景要加描边或投影）

## 8. 常见失败模式

| 症状 | 真实原因 |
|---|---|
| 「整体很花」 | 两个以上高饱和色，或纹理层不透明度太高 |
| 「看着廉价」 | `tint` 不是 accent 的淡化版，另起了色相 |
| 「不像一套」 | 色相没锚定，九个色各走各的 |
| 「夜里刺眼」 | 夜间 accent 照抄日间；正文用纯白 |
| 「字看不清」 | `faint` 对 `surface` 不足 4.5，最常见 |
| 「滚动头晕」 | 视差 depth 太大 |
| 「主题换了但没变」 | 站主开了主题轮播，轮播会覆盖手选预设 |
