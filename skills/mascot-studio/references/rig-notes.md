## 1. 为什么值得从位移场升级到骨架

位移场（SKILL.md §6）是**一张图 + 变形**：便宜、无需拆层，但天花板很低——
场只是 `(u,v)` 的函数，分不清同列的头发和手臂，也没有真正的层级。
实测结论：头、发、身能各自动，但**做不到"手抬起来""装置展开"这种跨部件的位姿变化**。

骨架是**N 张图 + 层级**：每个部件是刚体位图，只做 `translate/rotate/scale`。
代价是必须先拆层，收益是每个关节都能单独摆、能挂道具、能做 socket 附件。

判断标准（一句话）：

> 需求里出现「她拿着/戴着/展开某个东西」「不同姿势」「部件之间要遮挡正确」→ 骨架。
> 只有「头发飘、呼吸、头轻转」→ 位移场就够，别过度工程。

## 2. 拆层

用 See-through（`Mu-L/see-through`，单图 → 23 层 PSD + 遮挡补全）。本机是 8GB 显存，
bf16 跑不动（换页 30 分钟没完成），换 NF4（3.8GB）单张 4.5 分钟。

```bash
# 启动前必须：
export HF_ENDPOINT=https://hf-mirror.com   # 节点硬编码去 HF 拉 scheduler 配置
unset HTTP_PROXY HTTPS_PROXY               # 走系统代理直接 502
```

- `SeeThrough_SavePSD` 名不副实，只写 PNG + `layers.json`；要真 PSD 得用 pytoshop 自己拼。
- 输出 22–24 层，`legwear` / `footwear` 这类左右连在一起的用**连通域**（`scipy.ndimage.label`）
  按面积拆成左右，不要按中线切（中线会切到裙摆）。
- 每层裁到自己的 alpha bbox，记 `{x, y, w, h, z}` 写进 `parts.ts`——**这份坐标表就是骨架的骨架**。
- 人物本体**一个像素都不要改**，只切不改。改了就不再是"还原"。

> 拆层质量决定上限。拆错的层（比如头发和领口粘在一起）不要硬修，重跑拆层或手工补蒙版。

## 3. 骨骼层级

24 层 DOM，每层 `transform` 由骨骼链累乘得出（`root → hips → spine → chest → neck → head`），
`transform-origin` 全部用画布坐标写死（`transform-origin: 246px 700px`）。

### 3.1 后发不能是头的子元素

后发画在身体**后面**（z 序低于躯干），但它必须跟着头动。DOM 里做不到"既是头的子元素
又画在身体后面"。

标准解法是 **socket 挂点**：后发是独立节点，每帧取**头的世界矩阵**，乘上挂点的局部偏移再赋给后发。
这不是 hack，是所有引擎处理"跨绘制层但同骨骼"的通行做法。

```ts
// 每帧：把 head 的 world matrix 抄给 back hair，再叠自己的滞后
const m = matMul(headWorld, matMove(offsetX, offsetY));
backHair.style.transform = toCss(m);
```

### 3.2 发丝滞后

前发跟头走，后发用**弹簧追**同一个角度（而不是同一个值），才有甩动感：

```ts
S.hairBWorld.step(headAngleWorld, FIXED);   // hz 1.1, zeta 0.55
```

**"前半动、后半不动"的典型原因**：后发直接用了头的角度、或者干脆没接骨骼。
两个都要查。

## 4. 弹簧

`x += v·dt; v += (w0²(target−x) − 2ζw0·v)·dt`，`w0 = 2π·hz`。固定步长 **1/120s**，
每帧最多补 24 步（掉帧时不会爆炸）。

```ts
const FIXED = 1 / 120;
this.acc = Math.min(this.acc + raw, 0.1);     // 上限 0.1s，切后台回来不会一次补 5 秒
while (this.acc >= FIXED && n++ < 24) { ... }
```

| 部位 | hz | ζ | 理由 |
|---|---|---|---|
| 髋 / 腿 | 0.9–1.2 | 0.75–1.0 | 越重越软 |
| 胸 / 颈 | 1.2–1.6 | 0.8 | |
| 眉 | 2.6 | 0.78 | 比身体硬，否则像橡皮 |
| 嘴（张口） | 4.6 | 0.82 | 必须跟得住 34ms 的字形步长，见 §6 |
| 嘴（宽窄） | 5.2 | 0.9 | 同上，慢一点就变成装饰 |

### ⚠️ 初值必须等于静止值

`Spring(hz, zeta)` 默认 `x = 0`。位置类弹簧（`rootY`、`hipsX`）从 0 开始是对的，
**scale 类不是**——`scaleY(0)` 是"没有"，不是"没变"。

实测症状：hydrate 后第一帧写进 `scaleY(0)`，**嘴消失约 60ms 再胀回来**，
像眨眼眨到一半卡住。修法是给初值：`new Spring(4.6, 0.82, 1)`。

> 规则：**弹簧的初值要等于它"什么都没发生"时的值。** 位置是 0，比例是 1，角度是 0。

### ⚠️ kick 是速度冲量，不是位移

`kick(v)` 做的是 `this.v += v`。同一个数字在不同刚度上完全是两回事：

| 弹簧 | hz | `kick(-3.5)` 的峰值位移 |
|---|---|---|
| 装置（`monWorld`） | 0.55 | **0.5°** |
| 手臂（`armLR`） | 0.9 | 0.8° |
| 2 Hz 的关节 | 2.0 | 0.16° |

于是出现"调用处写着 3.5°，屏幕上看不见"的情况——而它并不是没生效，是被弹簧的刚度吃掉了。
凡是**要在屏幕上看得见**的冲量，都按位移给：

```ts
/** 按峰值位移给冲量，不是按初速度。 */
impulse(peak: number) {
  const w0 = 2 * Math.PI * this.hz;
  const wd = w0 * Math.sqrt(1 - this.zeta * this.zeta);
  const t = Math.atan(wd / (this.zeta * w0)) / wd;
  const gain = (Math.exp(-this.zeta * w0 * t) * Math.sin(wd * t)) / wd;
  this.v += peak / gain;
}
```

### ⚠️ 姿态是常量，反应是变量

给骨骼弹簧换目标值来做"姿态"（`FORM_POSE`）很方便，但**姿态值不能混进动态项**。
本项目：装置瞄准的弹簧吃了 `headR`，而 `headR` 里含着轨道炮态自己的"头低 4°"，
结果装置**永久倾斜 4.4°**——1150 单位高的物体，顶端偏 158 单位，读作"要倒了"。

> 规则：动态弹簧只吃**纯动态量**（待机转头、指针、冲量）。任何"这一态应该长这样"的
> 常量，走独立的姿态通道，两者最后相加。

### ⚠️ 挂在谁身上，就只跟谁

道具 socket 在髋上，就只跟 `hipsR`。跟 `chestR` 是错的：胸转不该带着髋上的东西倾。
"看起来都在动所以随便跟一个"是这类 bug 的唯一来源。

### ⚠️ 受击弹簧要和跟随弹簧分开

"世界角 − 父级角"这种写法里，冲量打在世界角上会被父级同向运动抵消。
要一个目标恒为 0 的独立弹簧（`monHit`），冲量才是它自己的动作。
ζ 取 0.4 左右（欠阻尼）——重物挂在托架上不会一条弧就停。

## 5. 表情：形状必须烤成位图

位移改不了形状。「皱眉」「露齿笑」不是位置变化，是**另一张图**。
所以表情分两层：

1. **离线烤的位图**：眉 4 形（`neutral`/`furrow`/`raise`/`drop`）、
   嘴 6 形（`neutral`/`smile`/`open`/`grin`/`pout`/`sleep`）。
2. **运行时的小位移**：几个像素的游走 + 1–2° 倾角，让形状不会僵在那里。

两层都要，但幅度要分工——**位图负责"是什么表情"，弹簧负责"表情在呼吸"**。
两者都开大会重复计算，看起来像抽搐。改了位图就要把对应的弹簧幅度调小：
本例里 `sleep` 的"眉垂"进了 `drop` 位图之后，弹簧从 +1.6px 收到 +0.6px，
否则眉条会被推进睫毛线。

### 5.0 每个状态必须靠「形状」可分辨

这条比"多烤几张图"重要。在 9 个显示像素下，**位置差看不出，轮廓差看得出**。
所以两个状态如果共用眉和嘴、只差弹簧偏移，它们就是同一张脸。

判断方法：把每个状态的 `(眉, 嘴, 腮红)` 写成三元组，**两两不能相同**。
本例第一版有两次撞车：

- `sleep` 用 `neutral`/`neutral` → 和 `idle` 一模一样。闭着眼的思考脸不是睡着的脸。
  → 补 `drop` + `sleep`（嘴角下垂、开口偏低偏扁）。
- `held` 和 `happy` 都用 `raise` + 泛红，嘴再都用 `open` → 又是同一张脸。
  → `held` 换成 `pout`（圆口）。

嘴的形状由三件事决定，三个都要分开调：

| | 嘴角 `corner` | 开口 `rx × ry` | 位置 `dy` | 读作 |
|---|---|---|---|---|
| `open` | −1.1 上抬 | 3.6 × 2.2 横椭圆 | +0.4 | 在说话 |
| `grin` | −1.1 | 4.8 × 2.9 + 牙带 | +0.2 | 露齿笑 |
| `pout` | −0.3 几乎不弯 | 2.2 × 2.4 **竖椭圆** | +0.2 | 「哦」/ 被吓到 |
| `sleep` | **+1.3 下垂** | 2.4 × 1.7 扁 | **+1.1 偏低** | 睡着、松弛 |

写一个矩阵脚本遍历所有状态 × 形态，断言三元组两两不同——比截图快，也比肉眼准。

### 5.1 细条用逐列亚像素位移

眉是 7–9px 高的细条，嘴是 20×19。这种尺寸**按列垂直平移就能改弧线**，
而且复用原像素——抗锯齿和颜色都是插画自己的，比重新画干净得多。

```python
# 每列按小数部分在相邻两个整数位移之间混合
s = dy[x]; k = floor(s); f = s - k
out[:, x] = shifted(col, k) * (1 - f) + shifted(col, k + 1) * f
```

**必须亚像素**：整像素平移时，45px 宽里每 9 列跳 1px，肉眼看成一道折角。

### 5.2 所有变体必须同尺寸

`transform-origin: 50% 50%` 是相对**元素自己的盒子**算的。`furrow` 7px 高、`neutral` 19px 时，
两者会绕相距 6px 的点旋转，倾斜时错位。

→ 生成器给每个变体烤进同样的透明边（`FACE_PAD = 6`），输出尺寸完全一致。

### 5.3 不能换 `src`

十个变体全部常驻 DOM，靠 `data-on` 切 `opacity` 交叉淡入。
换 `src` 会在第一次用到某个形状时闪一下未加载的图——用户第一次看到"生气"就是一张白脸。

### 5.4 组合规则要分层，不能"状态优先"

写"状态一律优先"的后果：每次切形态都附带一句台词 → 状态变 `talk` → 四形态的表情全被压成同一个。

正确分层：

| 谁 | 拥有 |
|---|---|
| **情绪**（happy / held / sleep） | 眉 + 嘴 |
| **形态/装备** | 只在她没有情绪时拥有 |
| **说话** | **只**让嘴张开（它不是一种心情） |

### 5.5 眼睛：不要靠缩放做「睁大」

一只眼通常是三层独立元素（眼白 / 虹膜 / 睫毛），**各自有自己的盒子**。
给三层都加 `scaleY(1.14)` 会让它们绕**各自的中心**缩放：虹膜的中心比眼白高 0.5px，
放大后就从眼白上方顶出去了——和 §5.2 是同一个坑，只是这次跨元素。

两条出路，按成本选：

- **要真"睁大"**：烤一张新的眼白位图（开口更高），或把三层的 `transform-origin`
  统一到同一个画布坐标点。后者更省，但改的是 CSS 而不是数据，容易漏。
- **不追求"睁大"**：靠抬眉 + 嘴形 + 腮红三件事表达"惊"。10 个显示像素下，眼睛那点
  变化本来也看不出来——本例最后选了这条，并在文档里写明"眼睑只有睁/闭两档"。

眼睑的**两档也要非对称**：眨眼是"瞬间闭、缓开"（78ms 只够 4 帧，缓闭就永远闭不上），
睡醒走同一条缓动路径，约 150ms 睁开。写成对称缓动，眨眼会变成眯眼。

## 6. 口型：没有音频时，按字形调度

**正弦脉动是错的**：`sin(t × 4.1Hz)` 会让每一句台词看起来一样，和内容完全无关。

正确做法是**用正在出现的那个字形驱动嘴形**。没有音频时，"声音"就是 CSS 逐字动画，
而它的日程是精确已知的：第 *i* 个字形在 `delay + i × speed` 出现。
把**打字机自己用的那两个数**交给嘴，两者同源，不存在两套计时器漂移。

```ts
rig.say([{ text: jp, delay: 0, speed: 34 }, { text: cn, delay: 360, speed: 20 }]);
```

### 6.1 五元音映射

日语假名是 mora-timed（一字一拍），一个假名对应一个元音，所以**按字驱动 = 按音节驱动**，
在假名文本上是准确的。

| | a | i | u | e | o |
|---|---|---|---|---|---|
| open | 0.95 | 0.50 | 0.38 | 0.62 | 0.78 |
| wide | 1.06 | 1.14 | 0.78 | 1.02 | 0.86 |

单个嘴位图只能靠 squash 表达区别：`i` 最扁、`u` 最圆。

特殊处理：`ん` 闭合、`っ` 保持上一个、`ー` 拉长、标点闭合；片假名按 `0x60` 折成平假名
再查表（行表只写一遍）。

### 6.2 边界（必须如实写进文档）

- **是音节级，不是音素级。** 汉字没有读音可用（「価値」是 かち，拿不到）；
  同一假名里的辅音（k/s/t 段）不改嘴形。
- 真音素级需要**音频 + 对齐数据**，是另一件事，不要假装做到了。

**汉字不要给"一个中性值"。** 最初的做法是所有 CJK 返回同一个 `open`，
结果一整句中文变成一条平线——比原来的正弦**更差**，因为连"活着"都没有了。
正确做法是用 code point 哈希出一个**稳定**伪元音：

```ts
let h = cp * 2654435761; h ^= h >>> 15; h = (h * 2246822519) >>> 0; h ^= h >>> 13;
const t = (h % 1000) / 1000;
return { open: 0.42 + t * 0.36, wide: 0.92 + (1 - t) * 0.14 };
```

哈希的价值在**确定性**：同一句永远同一段动画（不会每播一次都不一样），
不同句不雷同。这不是发音，但它让嘴有事可做。

### 6.3 收尾

最后一个字落地后要**自己闭回去**，且延迟 ~240ms——立刻闭嘴像被切了音轨。
由 rig 负责收尾，宿主不要维护计时器（两个计时器一定会漂）。

### 6.4 第二种宿主：文字一次性出现时

骨架角色的台词是逐字动画，日程已知。**内联 SVG 造型**的气泡文字是整段一次出现的，
没有逐字日程可跟。这时按说话速度**推导**一条日程（`scheduleForText()`）：

```ts
export function scheduleForText(text: string, step = 210): VisemeCue[] { … }
```

210ms/字 ≈ 中文口语 4–5 字/秒。这是估计，不是测量——文档里要这么写。

两个宿主的**唯一差别就是日程怎么来**，`visemeFor()` 是共用的，不要各写一份。

SVG 造型没有弹簧，用两个 CSS 变量 + `requestAnimationFrame` 手写指数平滑：

| 变量 | CSS | 含义 |
|---|---|---|
| `--ms-open` | `scaleY` | 开口 |
| `--ms-wide` | `scaleX` | 展唇 / 圆唇 |

```css
.ms-mouth-talk, .ms-mouth-grin { transform-box: fill-box; transform-origin: 50% 0; }
.ms-mouth-talk { transform: scale(var(--ms-wide, 1), var(--ms-open, 1)); }
.mascot { --ms-grin: calc(1 + (var(--ms-open, 1) - 1) * 0.7); }
.ms-mouth-grin { transform: scale(var(--ms-wide, 1), var(--ms-grin)); }
```

映射必须是 `REST + open × SPAN`，**REST 落在原尺寸附近**。写成 `0.55 + open × 0.8`
等于让嘴"说话时缩小"，实测行程 1.77px，屏幕上什么也没有。
上界由**下巴**决定：量出嘴到下巴的距离，取"最大开口时下唇还在脸内"的那个倍数。

笑嘴要驱动但压幅度（上面 `--ms-grin` 的 0.7）——满幅会把笑变成张大嘴。


## 7. 泛红用渐变，不用位图

`radial-gradient` × 2 + `mix-blend-mode: multiply`：

- 软、左右对称，比多一层位图便宜，也没有硬边。
- `multiply` 是**像皮肤而不像粉色贴纸**的关键——它把脸颊压暗，不是盖上去。
- z-index 夹在脸和眼睛之间（脸 10 / 眼 16 → 红晕 11），压在眼睛上就成了眼影。
- 由 `data-blush` 属性开关，CSS 负责淡入（0.45s），JS 只翻属性。

坐标从画布量：脸 x 171–305、眼 y 108–130 → 红晕落在 y 141（眼下、下颌上）。

## 8. 布局：比例要 1:1 就得让画板出血

装置/道具的"还原比例"常常被布局偷走。上一版对官图打了 20% 折扣，原因不是美术，是
两栏布局只给画板 1120px。

两步才够：

1. **改单栏**（控制面板移到人物下方）。
2. **画板 full bleed**：

```css
--plate-w: min(100vw - 48px, 1440px);
width: var(--plate-w);
margin-inline: calc((100% - var(--plate-w)) / 2);
```

⚠️ 那个负 margin **不是装饰**：grid item 比它的区域宽时，**不会**在 `justify-items: center`
下对称溢出，而是挂在右边、直接撑出横向滚动条。`100vw` 含滚动条宽度，所以留 48px。

结果：1:1 的下限从 1200px 前移到 **760px**。再窄才缩装置——因为 1:1 会让**人物**只剩
250px 宽，那时保装置比例、牺牲人物比反过来更难看。

⚠️ 画板高度要按**道具包围盒**留，不是按人物画布留。扇面上下都超出人物画布时，
`overflow: hidden` 会把尖端切掉。用 `:has()` 让非展开态收回留白，配过渡。

## 9. 验证（这一节最省时间）

### 9.1 采样必须在页面内循环，不能 CDP 往返

字形步长 34ms，而一次 `page.evaluate` 往返 ~45ms——**台阶会被整个跨过去**，
测出来全是"没动"。

```js
await page.evaluate(async () => {
  const t0 = performance.now();
  const out = [];
  for (let i = 0; i < 130; i++) {
    out.push([Math.round(performance.now() - t0), read()]);
    await new Promise((r) => setTimeout(r, 20));
  }
  return out;
});
```

### 9.2 判据要能区分"正弦"和"字形驱动"

正弦不会在两个相邻样本上重复；字形驱动会**驻留**在元音上。所以统计相邻样本重复率：

- 正弦 ≈ 0.1–0.2
- 字形驱动 **> 0.5**（本项目实测 0.91）

配一条：说话窗口内 `openMin ↔ openMax` 必须有明显跨度（实测 1.05 ↔ 1.67）。

### 9.3 别用"等开场台词出现"当起点

会只采到尾巴——整段是弹簧归位，看着像在动，其实什么也证明不了。
同理，**hydration 前的点击会被吞掉**，测出来的其实是自动开场那句。

### 9.4 读属性的正确名字

自己写的 `data-*` 属性和 `dataset` 的对应关系容易记错（`data-v` → `dataset.v`，
不是 `dataset.variant`）。选择器写错的表现是**字段静默消失**（`undefined` 被
`JSON.stringify` 丢掉），看起来像"没生效"，其实是没读到。
