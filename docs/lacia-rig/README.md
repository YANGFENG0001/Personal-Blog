## 1. 为什么这次不是"局部轻微移动"

> **先说清楚来路**：这套绑骨是我自己写的，**没有基于任何已发表的绑定方案**
> （不是 Live2D、不是 Spine、不是 VRM）。代价就是这类「两段头发各摆各的」问题
> 没有人替我兜住，只能自己发现、自己修——第 1 节末尾记了这次修的经过。

上一版用 SVG 位移场（`feDisplacementMap`）做动效，失败原因是数学层面的：
**权重 × 位移场 = 变化的旋转 = 剪切**。权重一软，躯干就被拧弯；权重一硬，边缘就死。

这一版换成真骨架：每根骨是一个 `transform-origin` 落在关节上的容器，
里面装刚体图层。旋转就是旋转，不会变成剪切。

```
root  (246,700)   ← 整体呼吸起伏
└ hips (246,700)  ← 重心左右移动 + 重量转移
  ├ legR (200,500) ─ kneeR (182,843) ─ ankleR (193.5,1132)
  │                  └ 小腿（靴子挂在踝里）
  ├ legL (300,500) ─ kneeL (303.5,824) ─ ankleL (281,1120)
  └ spine (246,700)
    └ chest (246,660)
      ├ armR (162,252) ─ elbowR (134.5,363) ─ wristR (79,536)
      │                  └ 前臂（手挂在腕里）
      ├ armL (318,250) ─ elbowL (355.5,348) ─ wristL (438,528)
      ├ torso (246,444)                    ← 呼吸缩放（只影响躯干）
      └ neck (235,214)
        └ head (235,186)
          └ hairFront (235,160)
hairBack (235,190)  ← 画在身体后面，所以不在 DOM 链里；靠世界矩阵跟随头骨
```

坐标单位是拆层图里的 1px（画布 493×1276）。

踝与腕是**嵌套**的，不是并列：踝装在膝里、腕装在肘里。小腿的切面在膝，
靴子的切面在踝——靴子若跟小腿同轴，膝一动脚底就跟着翻，读作"踩不到地"。

### 1.0 膝 / 踝 / 肘 / 腕：六段肢体，枢轴由脚本量出来

腿和手臂原本都是**一根刚体**（腿是大腿到脚踝一张图，手臂是肩到指尖一张图），只能绕
根关节转。表现就是"站得像立牌""伸手够不到装置"。现在四条肢体切成六段：

| 肢体 | 上段 → 骨 | 下段 → 骨 | 末段 → 骨 | 枢轴 |
|---|---|---|---|---|
| 右腿 | `legwear-r-up` → `legR` | `legwear-r-lo` → `kneeR` | `footwear-r` → `ankleR` | 膝 (182, 843) · 踝 (193.5, 1132) |
| 左腿 | `legwear-l-up` → `legL` | `legwear-l-lo` → `kneeL` | `footwear-l` → `ankleL` | 膝 (303.5, 824) · 踝 (281, 1120) |
| 右臂 | `handwear-r-up` → `armR` | `handwear-r-lo` → `elbowR` | `handwear-r-hand` → `wristR` | 肘 (134.5, 363) · 腕 (79, 536) |
| 左臂 | `handwear-l-up` → `armL` | `handwear-l-lo` → `elbowL` | `handwear-l-hand` → `wristL` | 肘 (355.5, 348) · 腕 (438, 528) |

- 切点不是硬编码的比例。`export_assets.py` 取**该肢体轮廓最窄的一行**作为关节线——
  直立人物那里正是上段收窄、关节开始的位置。第一版膝盖按 45% 硬切，落点低了 80px，
  切在小腿肚上，膝盖一动就"从小腿弯折"，像断了。
- **每个关节的搜索窗口都不一样，不能共用。** 手臂整体最窄的地方是**手腕**（实测占臂高
  64%、宽 28px），按腿那套 40%–60% 去找肘会切在腕上，得到一只会转的手；腕又必须在
  **前臂裁切**里找，不能在整条手臂里找，否则又切回肘。窗口是膝 40–60%、肘 25–50%、
  腕 60–78%、踝 02–30%（`JOINT_BANDS`）。
- **靴子不切两段，只取枢轴。** 踝不是可以把靴子劈开的地方；`footwear` 整张挂在
  `ankleR/ankleL` 里，枢轴取靴口（最窄行）。
- 两段**重叠 16px**（腕 9px，手小，重叠多了会吃掉指节）。旋转会在切面上张一个楔形
  口子，重叠把它盖住。实测到 **26°** 都看不出接缝。
- 枢轴 `LACIA_KNEE` / `LACIA_ELBOW` / `LACIA_WRIST` / `LACIA_ANKLE` 由脚本一并写进
  `parts.ts`，不手抄——切点和枢轴是同一个数，手抄一次就会在下次重切时错开。

**正视图里膝盖不是矢状面弯曲。** 这张图是正面站姿，真实的屈膝（脚跟往后）几乎看不见，
只能靠透视缩短。从正面读得出的是**小腿相对大腿的角度**，所以驱动写成反向旋转：
大腿在髋上摆多少，小腿就抵消 85%，脚不外滑，膝就"活"了。幅度约 0.5–5°，悬空态 9°。
**踝同理，而且更严格**：正面唯一读得出踝的是**鞋底的角度**，所以踝要反向抵消小腿的
80%，`|膝+踝|` 的峰值控制在 2.3° 以内（`verify/joints.cjs` 的 SOLE 项）。

**两条腿不能同相位。** 原来两条腿吃的是同一个 `sway` 表达式，动起来是一整块——这才是
"膝盖僵硬"的真正来源，不是幅度太小。现在每条腿两个不可通约的正弦，且**两条腿的
频率不同**（0.107/0.043 与 0.089/0.051）。只给一个正弦加相位差不够：两腿会拍频，
其中一条会连续几秒几乎不动，那本身也是一种僵。

**重量转移才是下半身"活"的关键。** 相位不同只解决"同手同脚"，仍然没有重心。加一个
`weight = sin(t·TAU·0.041 + 0.9)`（周期 24s，与 sway 的 12s 不可通约）：承重腿伸直
（膝屈量 ×0.55）、自由腿放松，髋随之平移。没有这一项，两条腿幅度再大也是一块板在晃。

**肘让"扶导轨"第一次成为可能。** 单段手臂时，手停在导轨前约 15px，姿态写的是"扶"，
画面是"伸"。加上肘以后，上臂摆出去、前臂折回来，指尖落到距导轨 **5px**——接触上了。
障壁态同理：前臂横过身体是只有两段手臂才能做的动作，实测手在躯干前重叠 146px。

**腕必须独立，而且要反向耦合。** 只拆到肘时，手焊死在前臂上，永远指着前臂的方向——
"扶着导轨"变成"戳着导轨"。腕的驱动写成 `-elbow × 0.28`：肘折进来，腕反向让手掌压回
平面。用 `+elbow × k` 会让手甩过前臂，像杆子上的旗。腕的弹簧更硬更欠阻尼
（1.45 / 0.5），因为它质量最小、最容易读出延迟。

**手臂要滞后于躯干。** 手臂相对躯干反向摆 `−torsoWorld × 0.45`。不补这一项，手臂跟着
身体一起转 = 肩是焊死的。头部同理但更强：`headR` 减去 `torsoWorld × 0.55`——站立时
身体摆几度、头几乎不动（实测头/髋相关 `−0.19`）。系数写成 1.0 会像鸡头。

**横过身体的肢体要抬层级。** `.lr-arm` 是 `z-index: 2`，`.lr-torso` 是 5，前臂折到
身前会被躯干盖住——"左小臂横挡"变成"左臂消失"。只在障壁态把 `.lr-arm` 提到 6；
全局抬高会让其余三态里近侧手臂压住髋甲。

### 1.0.1 躯干链：胸、腰、脖、腕（用户点名"太僵硬"的四处）

四肢做完了之后，剩下的僵硬全在**没有关节的那几段**：髋→腰→胸→胸廓→脖→头。这条链在
美术里是连成一片的，但动起来必须分级，否则整个人是一根棍子插在脚上。

四个改动，每个都有自己的失效方式：

- **腰（`spineR`）**：原来只有 `-sway × 0.3 + look × 0.45`，峰值 0.75°——等于没有。现在
  `-sway × 0.85 + weight × 0.5 + breath × 0.6 + look × 0.45`，峰值约 2°，弹簧也从
  0.9 Hz / ζ 0.85 放松到 0.72 / 0.72（约 1.4 s 回稳）。**比髋软、比髋欠阻尼**是重点：
  上身回位跟骨盆一样快，就等于腰以上没有质量。
- **胸（`chestR`）**：0.32° → 约 2.4°。它带动整条上身，所以头部补偿同步从 0.55 提到
  0.68——补偿提上去，看到的是**脖子动得多、头动得少**，这才是对的。
- **胸廓/胸部（`torso`）**：这是唯一能装 `topwear` 的骨头，也是唯一能让胸口**不跟着
  胸廓走**的地方。加了 `torsoR`（跟随 chest × 0.35，靠更软的 1.15 Hz / ζ 0.52 产生
  滞后）和 `torsoShift`（横向漂 1.6px，跟 `weight` 而不跟 `hipsX`，再减 `-hipsX × 0.35`
  让胸廓反着骨盆走）。呼吸缩放也从 1.1% 提到 1.8%。
  **耦合系数必须是正的**：写成 `-chest × k` 会让胸口反着胸廓转，正视图像胸口在歪。
- **脖（`neckR` + 新增 `neckX`）**：原来 `look × 1.1 + micro × 0.22`——指针不动它就
  完全不动，这就是"脖子僵硬"。现在加 0.9° 的呼吸漂、0.55° 的摇摆漂、0.5° 的微颤。
  更关键的是 `neckX`：**纯旋转让头绕弧线摆，仍然是一根棍子**；给一个横向位移，头才
  是"浮"在肩上而不是"装"在肩上。
- **腕**：行程从约 1.5° 提到约 4°，弹簧 1.45 / 0.5 → 1.05 / 0.42（过冲约 25%）。

**姿态常量不能进动态项。** `torsoR` / `torsoShift` / `neckX` 都要先减掉 `FORM_POSE` 的
偏移再算，否则轨道炮形态那个 `chest: 8` 会让胸口永久歪 2.8°、髋部 `hipsX: 6` 会让胸廓
永久偏 2.1px——和 `monAim` 不能吃 `headR` 是同一个错误。

`verify/secondary.cjs` 用四条独立判定守住它：RANGE（每段行程下限）、LAG（胸廓对 chest
的互相关峰必须落后 ≥2 帧）、GAIN（峰值相关 <0.97，否则就是 `chest × k` 没有弹簧）、
FLOAT（`neckX` 的横向变化 ≥0.8px）。实测：spine 3.22°、chest 4.63°、torso 2.56°、
neck 3.66°、head 6.07°，胸廓滞后 6 帧（约 170ms），`neckX` 3.52px，头/髋相关 −0.15。

> 互相关的**符号**很容易搞反：`corr(a[i+lag], b[i])` 的峰在**负** lag 才表示 `b` 落后。
> 把这一条写进脚本注释，否则一个正确的滞后会被读成红色。

### 1.0.2 姿态表：僵硬的真正病灶不在关节

关节和躯干链都做完之后，用户还是说"摆动作的时候身体僵硬"。原因不在弹簧，在
**`FORM_POSE` 只描述了腰部以上**：四个形态站在同一双直腿上，切形态时上半身换姿势、
下半身立正，轮廓在腰上断开。

更糟的是 `railgun` 当时写着 `rootY: 9`——把骨盆压低 9px，却没弯膝。**骨盆是被腿吊着
的**，链路的根在髋，压低 `rootY` 等于把脚一起压下去。实测鞋底比 `coffin` 低 10px，
也就是脚后跟沉进了地板。

修法是把腿也写进姿态表，并且**`rootY` 和膝角必须一起选**：唯一能吸收 `rootY` 的是
屈膝，比例约 `2.6px per 10°`（`L1·L2·(1−cos φ)/L`）。所以 `rootY: 2` 配 2.6° 的膝，
而不是 `rootY: 9` 配 0。

姿态表里 `shinR/shinL` 存的是**小腿的世界角**，不是膝的局部角——这样左右对称、读起来
不用做减法，膝角在驱动时算 `shin − leg`。

### 1.0.3 接触：她靠在装置上，不是站在装置旁边

参考立绘里她**左手平搭在棺体边缘**、髋部向装置一侧翘、远侧腿外撇放松。要做这个接触，
手臂必须是两段 IK，不是手调角度。

三个坑，按踩到的顺序：

- **肘是反关节约束。** 上臂 105 单位、前臂+手 260 单位，长度差 2.5 倍，手臂能到的区域
  是一个**甜甜圈形环带**，不是圆盘。够到胸高只能靠肘横过身体或抬到耳侧，两者都读作
  断肢。所以接触点要放在手臂**自然垂着够得到**的高度（髋高），而不是参考图里的胸高。
- **IK 的目标必须换到胸的坐标系。** 手臂挂在胸上，不是挂在髋上。用静止肩解 IK、而
  真实肩随胸呼吸移动 3px，掌心就会离导轨 3px 并且随呼吸振荡（实测 16px）。正确做法是
  `inv(worldChest) · deviceMatrix · anchor`。
- **装置矩阵必须绕插槽旋转。** `matRot` 只绕画布原点，离插槽 2121 单位；2° 瞄准会把
  1150 单位的装置横推 74 单位，读作"贴地平移"而不是"转头看"。`matAbout(..., 246, 700)`
  加 CSS 的 `transform-origin` 两处都要改。

两个解（肘上 / 肘下）按**几何**选——取屏幕上更低的那个，不写死符号。写死会让肘抬到
耳侧，截图一眼就看出来。

### 1.0.4 `stance.cjs` 的判据：别拿包围盒当尺子

`verify/stance.cjs` 守四件事：PLANT（四形态鞋底一致 ±4px）、STANCE（站距互不相同 ≥3px）、
CONTACT（掌心在装置上且不漂）、ALIVE（胸行程 >0.4°）+ idle 骨盆不摇（<3°）。

CONTACT 一开始写的是 `palmX − edgeL > 150`——"掌心扎进导轨 150px"。**这个数在测包围盒，
不在测导轨。** 装置绕插槽转 2°，1100 单位的物体自己的包围盒角就会横移 70px，于是同一份
没改过的代码连跑两次给出 142 和 172。

正确的度量是**掌心到插槽的距离**：掌心钉在装置坐标系的固定点上，装置转动时这个向量跟着
转、长度不变。实测 railgun 10–19px、shield 2.5px——shield 稳是因为它的锚绑在骨盆上，
不跟装置动。阈值 25px 是**滞后预算**（手臂是弹簧，追一个在动的目标），不是放水。

同理，采样前必须把指针停在舞台中央：`monAim` 吃指针位置，不固定就等于让瞄准状态成为
噪声的一部分。

### 1.1 头发曾经"前半动、后半不动"，原因有两个

用户报的现象是真的，两个独立缺陷叠在一起：

1. **后发根本不吃身体动作**。`hairBack` 为了画在身体后面，DOM 上挂在 `.lr-bones`
   下面，是 `.lr-root` 的**兄弟**而不是子节点 —— 于是 hips/spine/chest/neck 的旋转和
   位移它一样都收不到，只拿到一个 `headR` 的数值。她身体一晃，后发原地不动。
2. **前发和后发的驱动项反相**。前发目标 `-0.22·headR - 0.3·micro`，后发
   `-0.55·headR + 0.55·micro` —— 同一个 `micro` 一个取负一个取正，两段头发会朝
   相反方向摆。

修法用的是 **spring bone 的标准形式**，不是调参数：

- 两个弹簧改为跟踪**头部世界角** `φ`（= 各节旋转之和），局部角 = 弹簧到达的世界角 − φ。
  静止时恒为 0，摆动时天然同向，只差滞后量。`micro` 项直接删掉。
- 后发改用**世界矩阵**：每帧算 `root·hips·spine·chest·neck·head` 的合成矩阵，
  再左乘一段绕发根的滞后旋转，整体写进 `transform: matrix(...)`。
  这样它既画在身体后面，又完全跟着身体走 —— 就是引擎里「把道具挂到 socket」的做法。
- `poke` / 切形态不再单独 `kick` 头发：头一动，滞后自己会出来。人为补偿只会再制造
  一次不同步。

实测（60 帧采样，含一次头部冲击）：静止时局部角均值 `-0.07°` / `-0.05°`，
27 组有效样本里**反向 0 次**；后发矩阵的平移分量逐帧变化，证明它确实在跟身体。

## 2. 动作从哪来

每根骨一条阻尼弹簧（`ω=2π·hz`，`ζ=zeta`），按 1/120 s 定步长积分。

| 通道 | hz | ζ | 作用 |
|---|---|---|---|
| torso scaleY | 0.6 | 1.0 | 呼吸，±1.1% |
| hips rot / x | 0.7 | 0.9 | 重心左右，12 s 周期 |
| head rot | 1.15 | 0.62 | 欠阻尼，带一点点过冲 |
| hairFront（跟踪头部世界角） | 1.7 | 0.55 | 前发短，跟得紧 |
| hairBack（跟踪头部世界角） | 0.95 | 0.3 | 后发长而软，滞后明显 |
| monolith y/rot | 0.42 / 0.3 | — | 装置独立悬浮（叠加在 hips 世界矩阵上） |

头发两条弹簧的**输入是同一个量**（头部世界角 φ），输出取差值 `弹簧角 − φ`，
所以两者只可能在滞后量上不同，不可能反向（见 §1.1）。

另有三层叠加：

- **视线跟随**：指针位置 → 头部 ±2.9°、身体 ±0.45°（以 420px 为满偏半径，所以
  320px 的角落看板娘和 640px 的展示页手感一致）
- **待机转头**：每 4.8–11 s 随机取一个 ±4.5° 的方位，弹簧过去（所以不会机械地摆）
- **眼动跳视**：虹膜每 0.7–2.8 s 跳到一个新的 ±1.5px 偏移，**不是滑动**——真人眼球是跳的
- **眨眼**：2.6–6.2 s 一次，28% 概率连眨两下，78 ms 完成

## 3. 武器：BLACK MONOLITH

### 3.1 比例是怎么定的（有出处，不是估的）

比例来自实测：**GSC 1/8「レイシア 2018 BLACK MONOLITH 展開ver.」官方成品图**
（hpoi 词条 42052，原画/监修 redjuice，原型 上連小夜子）。

对着「展开 Ver.」的多角度官图量出来的相对关系：

| 量 | 官图读数 | 本实现（画布单位，她身高 = 1276） |
|---|---|---|
| 单片板长 | ≈ 0.85–0.9 倍身高 | **1085（= 0.85 倍身高）**，最外两片 830 |
| 单片板宽 / 板长 | ≈ 0.15 | 0.152（根部 0.076×2） |
| 镜头组件直径 | ≈ 0.75 倍头高 | 216（≈ 0.8 倍头高） |
| 展开后整体横向跨度 | ≈ 1.6 倍身高 | **2418（= 1.90 倍身高）**，含脱离片与刀尖 |
| 枢轴位置 | 腰后（她的髋部） | 画布 (246, 700)，即 hips 枢轴 |

**上一版对官图打了 20% 折扣（板长 0.66 倍），这一版取消了折扣。** 折扣的原因不是
美术判断，是布局放不下：1:1 的扇面要 1.9 倍身高的宽度，两栏布局（400px 文字栏 +
人物）在 1120px 容器里塞不进去。改法是两步：**把 /lacia 改成单栏**（控制面板移到人物
下方），再让**画板出血**到 wrap 之外——两栏变单栏还不够，wrap 的内边距仍然只给它 1120px
（见 §3.5）。

跨度 1.90 倍比官图量的 1.6 倍大，因为官图那台是**收着拍的**——八片没有全部展开到
极限，而且我的实现里多了一片沿轴外移的脱离片。板长按 0.85 走，跨度是它的几何后果，
不是另一个独立参数。

**"1:1" 的边界**：760px 以上的视口都是真 1:1（`--lr-mon-k: 1`）。画板先出血到
`min(100vw − 48px, 1440px)`，把 wrap 的内边距让出来，1:1 的下限才从 1200px 前移到 760px
（见 §3.5）。再窄只能缩装置——因为 1:1 会让**人物**只剩 250px 宽。每个断点的 k 都是按
"扇面包围盒 ≤ 画板"实测出来的，不是估的：

| 视口 | 画板宽 | `--lr-u` | `--lr-mon-k` | 实际板长/身高 |
|---|---|---|---|---|
| ≥1400 | 1352–1392 | 640 | 1 | **0.85（1:1）** |
| 1200–1399 | 1152–1352 | 560 | 1 | **0.85（1:1）** |
| 1024–1199 | 976–1152 | 470 | 1 | **0.85（1:1）** |
| 900–1023 | 852–976 | 410 | 1 | **0.85（1:1）** |
| 760–899 | 712–852 | 340 | 1 | **0.85（1:1）** |
| 600–759 | 552–712 | 320 | 0.82 | 0.70 |
| <600 | 372–552 | 280 | 0.66 | 0.56 |

实测余量（扇面包围盒到画板边缘，八个视口）：

| 视口 | 左 | 右 | 上 | 下 | `overflow` |
|---|---|---|---|---|---|
| 1440 | 78 | 113 | −9 | 20 | 0 |
| 1400 | 60 | 92 | −10 | 21 | 0 |
| 1200 | 36 | 65 | −8 | 18 | 0 |
| 1024 | 35 | 59 | −7 | 16 | 0 |

| 600 | 24 | 36 | 40 | 48 | 0 |
| 420 | 8 | 17 | 24 | 10 | 0 |

上排那几个负值是**旋转包围盒的空角**，不是实际像素（刀尖真径 1209 单位，画板半宽 ≥1233），
截图逐档确认过没有切边。600 / 420 两档上下余量突然变大，是因为 `--lr-mon-k < 1` 之后
扇面已经回到人物画布以内，`:has()` 把画板的额外留白收掉了。

**`--lr-mon-k` 只缩放硬件，不缩放投影。** 障壁那一簇七片在 `.lr-bm-scale` 里，会跟着
设备一起朝枢轴（她的腰）缩小——角落看板娘是 0.5，结果七片缩到她胯上，读起来像条裙子
而不是障壁。所以 `.lr-shield` 反向补偿 `scale(calc(1 / var(--lr-mon-k)))`：**场是按她的
身体投出来的，不是按设备的比例做出来的**，任何 `--lr-mon-k` 下都该罩住躯干；棺体和导轨
则继续缩小，因为那些确实是硬件，缩小是对的。

补偿的原点必须是 `0 0`（= 枢轴），不能照抄 `.lr-bm-scale` 的 `1500px 1500px`：这个组
已经在 `translate(1500 1500)` 里面，`1500px 1500px` 会被解析成局部坐标，把整簇甩到画外
1500 单位——实测表现是「护盾整组消失，只剩腰间那个小六边形」。

### 3.2 她怎么用它

官图上她**不握着它**：装置从她腰后放射出去，她站在结构前面。
所以实现上不是「手持道具」，而是：

- **socket 挂点**：整个 SVG 不挂在 DOM 骨骼链上（它必须画在人物后面），
  由 `rig.ts` 每帧算出 `hips` 的世界矩阵，把装置乘上去 —— 她重心一晃，装置跟着晃。
  这是引擎里挂道具的标准做法，不是特例。
- 展开时八片板从腰后枢轴向外张开，其中一片带镜头组件。
- 设定原文（见 3.3）里「内部八爪可分离，其中一支共享感官作目标护卫」，
  在展开态里表现为**带镜头的那片沿自身轴向外移 80 单位**，根部与枢轴环之间留出
  74 单位的空档（`.lr-slab.is-free`）。

  早先这里是一个独立的 `.lr-escort` 爪组，绕了三个方位都放不下：它要"脱离"就得比
  扇面半径（1053）更远，而画板横向只剩 180 单位的余量、纵向上下各只剩 ~200。
  换成"让八片之一自己走"以后，代价只有 80 单位宽度、纵向零增加，而且更贴设定
  ——原文说的是"八爪之一"，不是第九个东西。

#### 3.2.1 联动是四个弹簧，不是一句话

"装置跟着她动"拆开是四项，各自有各自的对象，混在一起就会互相抵消：

| 弹簧 | 目标 | 管什么 |
|---|---|---|
| `monWorld` | `hipsR.x` | **滞后**。与头发同一套写法：局部量 = 世界角 − 父级角，静止时恒为 0，只在运动中出现 |
| `monAim` | `headTurn × 0.45 + 指针 × 2.4`（轨道炮态 ×1.35） | **瞄准**。她转头，膛口跟着转 |
| `monR` | 正弦 ±0.8° | **待机游走**，让它看起来是浮着而不是钉死 |
| `monHit` | 0 | **自身受击**。切形态的后坐、被点时的震动 |

`monHit` 必须是独立弹簧。`monWorld` 的目标是 `hipsR`，冲量打在上面会被"她的髋也朝
同一方向动"抵消掉大半 —— 调用处写的是 3.5°，屏幕上只剩 0.5°，而且看起来像没反应。
给它一个目标恒为 0 的弹簧，冲量就完全是装置自己的动作。

**冲量要按位移给，不能按速度给。** `Spring.kick(v)` 加的是速度，同一个数字在不同
刚度的弹簧上完全是两回事：`kick(-3.5)` 在装置（0.55 Hz）上峰值 0.5°，在 2 Hz 的
关节上是 0.16°。所以加了 `Spring.impulse(peak)`，按"我想要几度的峰"反解初速度：

```
t_peak = atan(wd / (ζ·w0)) / wd
gain   = e^(−ζ·w0·t_peak) · sin(wd·t_peak) / wd
v0     = peak / gain
```

装置的数值：被点 −2.6°、轨道炮 −3.2°、八爪展开 −4.4°（八片同时锁死，是四态里最重的
一次）。`monHit` 的 ζ 取 0.42，故意欠阻尼 —— 1150 单位的东西挂在托架上不会一条弧就停。

**姿态角不是动态响应。** `monAim` 只能吃 `headTurn`（待机转头）和指针，绝不能吃
`headR`：`headR` 里含着形态姿态自己的偏移，轨道炮态"头低 4°"会让装置永久倾斜 4.4°，
在 1150 单位高的物体上是 158 单位的偏移，读作"要倒了"。同理 `monWorld` 只跟 `hipsR`，
不跟 `chestR` —— 装置挂在髋上，胸转不该带着它倾。

实测（`verify/linkage.cjs`，连跑三次通过）：指针左右移动 → 装置摆 2.0–2.6°；
点她一下 → 逐帧变化率 0.9°/帧，待机时是 0.06–0.11°/帧（差 8–9 倍）；
切轨道炮 → 27 帧里有 14–18 个不同的中间角度。

### 3.4 四形态：位置、姿态、台词

姿态不是硬切，是给骨骼弹簧换**目标值**，所以切换会自己缓动过去（`FORM_POSE`）。
下表的角度就是 `FORM_POSE` 里的数，不是设计意图的描述 —— 早先这里写着"右臂抬起 30°
扶导轨"，而代码里是 `armR: 8`，两者对不上，而且**扶导轨的那条手臂根本不是右臂**。

| 形态 | 装置位置 | 她的姿态（`FORM_POSE` 实际值） | 台词（原创，非作品原句） |
|---|---|---|---|
| 收束 CASKET | 画面右侧（她左手侧）腰外，竖直棺体 | 全零：站立，重心中性 | 棺体闭合。演算核心待机中。 |
| 轨道炮 RAILGUN | 同侧，双导轨 + 顶部环状炮口 | 根下移 9、髋转 6°、脊 3°、胸 8°、**近侧 `armL` 外展 26°**、`armR` 8°、头低 4° | 「質量投射」。要开火吗——请下命令。 |
| 障壁 BARRIER | 身前，覆盖躯干 | 根上移 3、髋转 −5°、脊 −2°、胸 −7°、`armL` 24°、`armR` −6°、头低 6° | 障壁展开。站到我后面。 |
| 展开 DEPLOY | 腰后枢轴，八片放射 | 根上移 5、脊 1°、胸 3°、`armR` 17° / `armL` −17°、头抬 3° | 八爪分离。其中一支，跟着你。 |

**手臂的符号是按坐标定的，不是按直觉定的。** 装置在画布 x 398–546，近侧那只手的枢轴在
318,250（`armL`），所以 `armL` 的**负值是向外**、指向装置。第一版写的是 `armL: +14`，
注释说"扶导轨"，画面上是"抱着自己"。`armR` 的枢轴在 162,252，符号正好相反：正值向外。
这类错误调参调不出来，只能把两边的坐标摆在一起看。

**表情**：眉毛和嘴是独立图层（`eyebrow-l/-r`、`mouth`），但**每种只有一个位图**。
位移解决不了"皱眉"和"露齿笑"——那是形状，不是位置。所以这一版把缺的形状**烤成了真位图**，
生成器是 `docs/lacia-rig/gen_face_variants.py`。运行时只写 `transform` 和 `opacity`，
不做任何位图变形。

| 特征 | 变体 | 怎么来的 |
|---|---|---|
| 眉 | `neutral` / `furrow`（皱眉，内端下沉）/ `raise`（扬眉，整条抬高变平）/ `drop`（垂眉，整条下沉、外端更垂） | **逐列垂直位移**原图：眉是 7–9px 高的细条，按列平移就够改弧线，而且复用原像素，抗锯齿和颜色都是插画自己的 |
| 嘴 | `neutral` / `smile`（嘴角上扬）/ `open`（微张）/ `grin`（露齿笑）/ `pout`（圆口）/ `sleep`（松弛下垂） | `smile` 同样是逐列位移（两端上抬、中间不动）；`open` / `grin` / `pout` / `sleep` 是"弯不出来"的形状，用嘴自己的最深色画椭圆，8 倍超采样后缩回去 |

`grin` 不是 `open` 加宽一点就算：20px 宽的嘴如果只是张大，读出来是**在喊**，不是笑。
所以它比 `open` 更宽（rx 4.8 vs 3.6、ry 2.9 vs 2.2），并在开口上半部压一条白带 + 一道门牙缝。
在 9 个显示像素的高度里，一条牙带已经是"露齿"能表达的全部了。

`pout` 和 `sleep` 是同一条思路的另一面：**嘴的形状由"椭圆画在哪、有多大、嘴角朝哪边弯"决定**，
三者都要分开调。

| | 嘴角 `corner` | 开口 `rx × ry` | 位置 `dy` | 读作 |
|---|---|---|---|---|
| `open` | −1.1（上抬） | 3.6 × 2.2（横椭圆） | +0.4 | 在说话 |
| `grin` | −1.1 | 4.8 × 2.9 + 牙带 | +0.2 | 露齿笑 |
| `pout` | −0.3（几乎不弯） | 2.2 × 2.4（**竖椭圆，接近圆**） | +0.2 | 「哦」/ 被吓到 |
| `sleep` | **+1.3（下垂）** | 2.4 × 1.7（扁） | **+1.1（偏低）** | 睡着、松弛 |

**五个状态必须靠"形状"就能分辨**，因为 9 个显示像素下位置差看不出、轮廓差看得出。
旧映射里 `sleep` 用的是 `neutral`/`neutral`——那是"闭着眼的思考脸"，不是睡着的脸；
`held` 和 `happy` 共用 `open` 时也一样，两者都抬眉都泛红，嘴再一样就成了同一张脸。

三个细节，都是踩过才知道的：

1. **必须亚像素。** 一开始按整像素平移，45px 宽的眉里每 9 列跳 1px，肉眼直接看成一道折角。
   改成按小数部分在相邻两个整数位移之间混合才连续。
2. **所有变体必须同尺寸。** `transform-origin: 50% 50%` 是相对元素自己的盒子算的，
   如果 `furrow` 是 7px 高、`neutral` 是 19px，两者会绕相距 6px 的点旋转，倾斜时错位。
   所以生成器统一给每个变体烤进 `FACE_PAD = 6` 的透明边（`face.ts` 里的常量）。
3. **不能换 `src`。** 十四个变体全部常驻 DOM，靠 `data-on` 切 `opacity` 交叉淡入；
   换 `src` 会在第一次用到某个形状时闪一下未加载的图。

连续位移那一层**没有删掉，但幅度调小了**（`EXPR_STATE` / `EXPR_FORM`）：形状由位图负责，
弹簧只负责几个像素的游走和 1–2 度的倾角，否则会把表情重复计算两次。
`sleep` 就是这条规则的实例——眉的"垂"已经在 `drop` 位图里，弹簧只再加 0.6px；
写成原来的 1.6px 会把眉条推进她的睫毛线。

组合规则不是简单的"状态优先"：**情绪**（happy / held / sleep）拥有眉和嘴；**形态**只在她
没有情绪时拥有；**说话只让嘴张开**，因为它不是一种心情。早先写的是"状态一律优先"，
结果每次手动切形态都会附带一句台词 → 状态变成 `talk` → 四形态的表情全被压成同一个，
看起来像没做。

**五个状态 + 四个形态的完整映射**（`face.ts` 的 `STATE_FACE` / `FORM_FACE`，实测见下）：

| | 眉 | 嘴 | 泛红 | 眼 |
|---|---|---|---|---|
| idle | neutral | neutral | — | 睁，视线游走 + 眨眼 |
| talk | neutral | open（字形驱动） | — | 睁 |
| happy | raise | **grin** | ✅ | 睁 |
| held | raise | **pout** | ✅ | 睁 |
| sleep | **drop** | **sleep** | — | **闭** |
| coffin | neutral | neutral | — | 睁 |
| railgun | furrow | neutral | — | 睁，视线锁定 |
| shield | furrow | open | — | 睁 |
| unfold | raise | smile | — | 睁 |

眼睑只有"睁 / 闭"两档，**没有"睁大"**：一只眼是三层独立元素（眼白 / 虹膜 / 睫毛），
各自有自己的盒子，整体放大 1.14 倍会让三层绕不同的点缩放，虹膜会从眼白上方顶出去。
要真的"睁大"得烤一张新的眼白位图，而 10 个显示像素下收益看不出来——所以 `held` 的
"惊"是靠抬眉 2.2px + 圆口 + 泛红三件事一起给的。

#### 口型：字形驱动，不是正弦

上一版的嘴是 `sin(t × 4.1Hz)` 的脉动——它在动，但和她说什么完全无关，任何一句话看起来都一样。

这一版（`src/lib/lacia/viseme.ts`）改成**按正在出现的那个字形决定嘴形**。
这里没有音频，"声音"就是 CSS 逐字动画，而它的日程是精确已知的：第 *i* 个字形在
`delay + i × speed` 出现。`say()` 拿到的是**打字机自己用的那两个数**，所以嘴张开的时刻
和字形出现的时刻是同一个数，不存在两套计时器漂移。

五元音映射 `(open, wide)`：

| | a | i | u | e | o |
|---|---|---|---|---|---|
| open | 0.95 | 0.50 | 0.38 | 0.62 | 0.78 |
| wide | 1.06 | 1.14 | 0.78 | 1.02 | 0.86 |

单个嘴位图只能靠 squash 表达区别：`i` 最扁、`u` 最圆。特殊处理：`ん` 闭合、`っ` 保持上一个、
`ー` 拉长、标点闭合；片假名先按 0x60 折成平假名再查表，行表只写一遍。

**这条边界的诚实说法：这是音节级，不是音素级。** 日语假名是 mora-timed（一字一拍），
一个假名对应一个元音，所以按字驱动就是按音节驱动——这在假名文本上是准确的。
但汉字没有读音可用（「価値」是 かち，我拿不到），只能给中性中间值；同一个假名里的辅音
（k / s / t 段）也不会改变嘴形。要真做音素级，需要音频 + 对齐数据，那是另一件事。

两条兜底：只调 `setState('talk')` 的宿主（角落看板娘，气泡时序在 `Mascot.astro`）
拿不到日程，仍走旧的 4.1Hz 脉动；最后一个字落地后 `say()` 自己清空脚本，
嘴会**闭回去**而不是冻在半开——用 `last + 240ms` 收尾，因为最后一个字立刻闭嘴像被切了音轨。

#### 泛红：渐变，不是位图

`happy` / `held` 时两颊泛红（`BLUSH_STATES`）。没用差分图：泛红是软且左右对称的，
两个 `radial-gradient` 比多一层位图便宜，也不会有边缘。

- 位置取自画布坐标：脸 x 171–305、眼 y 108–130，所以红晕落在 y 141（眼下方、下颌上方）
- z-index 11，夹在脸（10）和眼睛（16）之间——压在眼睛上就成了眼影
- `mix-blend-mode: multiply` 是让它像**皮肤**而不是粉色贴纸的关键：它把脸颊压暗，不是盖上去
- 由 `data-blush` 属性开关，CSS 负责 0.45s 淡入，JS 只翻属性

**还是做不到的**：真音素级口型（需音频）、鼻梁皱/眼神失焦/睁大眼睛这类新形状（需新差分图）、
泛红的**强度**渐变（现在只有 on/off，做渐变得让 JS 写 CSS 变量，收益不值这个复杂度）。
眼睑也还是"睁 / 闭"两档，闭是 `scaleY(0.07)` 压出来的，不是画出来的——所以眨眼时
睫毛会跟着一起压扁，78ms 里看不出来，但定格看是能看出来的。

（更早一版这里写的是「24 层里没有眉/口图层，表情做不了」——那句是错的，图层一直在，
只是从来没被驱动过。）

### 3.5 布局：为什么改成单栏，又为什么要"出血"

原来 /lacia 是两栏（400px 文字 + 人物），画板宽度只有 `1.34 × 人物高`。
1:1 的扇面要 `1.90 × 人物高`，两栏里放不下，上一版就是在这里打的 20% 折扣。

现在改成**单栏**：控制面板移到人物下方排成两行（`say | voices` / `console | spec`），
画板高度也不是人物高，而是 `人物高 + 0.22×2`——扇面上下都超出人物画布
（上方 936 单位、下方 892 单位，从枢轴算），不额外留白的话 `overflow: hidden`
会把四条斜板的尖端切掉。非展开态那三态本就在画布内，用 `:has()` 把上下留白收到 0.07，
配 0.5s 过渡，切到展开态时画板自己长高。

单栏还不够：wrap 还有内边距，画板最多拿到 1120px。所以画板**突破 wrap**（full bleed）：

```css
--plate-w: min(100vw - 48px, 1440px);
margin-inline: calc((100% - var(--plate-w)) / 2);
```

那个负 margin 不是装饰，是必须的：grid item 比它的区域宽时，**不会**在
`justify-items: center` 下对称溢出，而是挂在右边，直接撑出横向滚动条。
`100vw` 含滚动条宽度，所以留 48px。

结果是 1:1 的下限从 1200px 前移到 **760px**。八档实测（`overflow` 全部为 0）：

| 视口 | 画板宽 | `--lr-u` | 装置 k | 扇面左余 | 右余 |
|---|---|---|---|---|---|
| 1440 | 1392 | 640 | 1 | 78 | 113 |
| 1200 | 1152 | 560 | 1 | 36 | 65 |
| 1024 | 976 | 470 | 1 | 35 | 59 |
| 900 | 852 | 410 | 1 | 31 | 52 |
| 760 | 712 | 340 | 1 | 28 | 46 |
| 600 | 552 | 320 | 0.82 | 24 | 36 |
| 420 | 372 | 280 | 0.66 | 8 | 17 |

760px 以下才缩装置，因为 1:1 会让**人物**只剩 250px 宽——那时保住装置比例、牺牲人物
比反过来更难看。角落看板娘是另一套：0.66 / 0.82 / 1 三档跟着视口走，它是页面角落的
小挂件，1:1 的扇面会直接盖住正文。**`/lacia` 展示页才是 1:1 的读法。**

**怎么切形态**：点装置本体就切下一形态（这正好对应设定里的「解除 device lock」）。
展示页另有控制台按钮；角落里她会自己在待机时轮换——收束态停 15–23 s，
其它形态各停 6–8 s，轮换不打断台词。

### 3.6 画法：装置和角色必须是同一种媒介

角色是绘制的插画——没有一条线稿，所有边缘都是明度转折。装置第一版反着画：平涂填充
加亮色 2.6px 描边，单独看没问题，并排就是"一个是画出来的、一个是蓝图"。**比例、颜色
都对，媒介不对，读起来仍然像两个东西拼在一起。**

改法只有一条：**删掉轮廓描边，让明度承担轮廓。**

| 部件 | 改前 | 改后 |
|---|---|---|
| `.lr-half-plate` | `stroke .44 / 2.6px` | `stroke .14 / 1.8px`（边缘微光，不是线） |
| `.lr-half-face` | 平涂 `rgba(5,8,13,.66)` + 描边 | 自己的 `face` 渐变，无描边 |
| `.lr-half-sheen` | `.07 / 12px` | `.17 / 30px`（唯一的高光，要单独扛住"抛光金属"） |
| `.lr-slab-body` | `stroke .36 / 2.4px` | `stroke .12 / 1.6px` |
| `.lr-slab-tip` | `.85` | `.55`（受光棱边保留实线——那是高光不是描边） |
| 切口 / 格栅 / 走线槽 | `.13–.24` | `.06–.12`（表面细节，不是线稿） |

两个坑：

1. **内嵌面板盖掉了底板的渐变。** `.lr-half-face` 占正面 85% 面积，原来是一层 72%
   不透明的纯黑，底板做得再好的 `slab` 渐变也只剩边上一圈——这才是棺材"一个色"的
   真正原因。它现在有自己的 `face` 渐变（`monolith.ts` 的 `<defs>` 里）。
2. **线框会从高光里回来。** 删掉描边后第一反应是把剩下的线加亮：`glint` 提到
   `.62 / 4.2` 之后它成了画面最亮的东西，八片板读成八条放射线。压回 `.3 / 3`。

```ts

rig.say([{ text, delay, speed }])   // 打字日程 → 口型；rig 自己负责收尾
```

所以 JS 没加载完也能看见她站着，只是不动。

看板娘那边靠事件解耦，`Mascot.astro` 完全不知道骨架的存在：

| 事件 | 方向 | 用途 |
|---|---|---|
| `lacia:state` | Mascot → rig | 说话 / 开心 / 被拎起 / 睡觉 |
| `lacia:poke` | Mascot → rig | 点击反应 |
| `lacia:form` | rig → Mascot | 形态变了，取出对应 `LINE_GROUPS` 的台词 |

### 6.1 第二套皮肤：蓝裙也要是骨架，不是一张图

用户的要求是"同级别"——所以不能拿静态立绘糊过去（那样会丢掉关节、表情、口型和武器接触）。
做法是**再造一副同构的 30 层**，让 `LaciaSkin` 二选一。

流程五步，每一步都有一个能毁掉整件事的坑：

1. **换装**：以 `lacia_idle.png`（原立绘）作为 img2img 的结构输入，prompt 只描述衣服。
   用别的立绘当参考会让姿势漂移，枢轴就全废了。
2. **对齐**：把生成图的 alpha bbox 缩放到与原立绘**完全相同的 bbox**。这一步之后，
   两套画布是 493×1275 与 493×1276 —— 差 1px，所有手工枢轴（肩、髋、脖）直接通用。
3. **拆层**：同一个 See-through 工作流，只改输入图与前缀。工作流已归档到
   `docs/seethrough-dress/workflow.json`，`docs/lacia-rig/pipeline/run_st.py` 就是拿它
   POST `/prompt` 复现的那几行。`.ref/` 是 gitignored 的草稿目录（生图底稿、参考图、
   对照截图），**脚本本身不在那儿**——出图 / 抠图 / 拆层三个脚本在
   `docs/lacia-rig/pipeline/`。
4. **后处理**：见下面的清单，四件事缺一不可。
5. **导出**：`export_assets.py` 带 `--src/--meta/--out/--ts/--name`，写到独立目录和独立
   `parts-dress.ts`，绝不覆盖原皮肤。转正后的素材在 `docs/seethrough-dress/`，
   重跑一次 `parts-dress.ts` 与 30 张 webp 应当字节一致（见该目录的 README）。

**坑一：裙摆会抢走整条手臂。** 第一版立绘是蓬 A 字裙，See-through 把**整条裙摆**
判给了 `handwear-l`（左臂），三层全是裙子，左手彻底丢失，脸上还多了一块灰色。
换 seed 不是解法——蓬裙和手臂在空间上重叠，模型只能二选一。真正的解法是**改图**：
把裙摆画成贴腿的直筒，让手臂和裙子之间有可见间隙。第二版就干净了。

**坑二：鞋子整层丢失。** 第二版 21 层里没有 `footwear`，脚是裸的。低跟鞋在模型眼里
不像"鞋"（没有靴筒）。补法是几何的：鞋是膝以下唯一的近黑区域，从对齐图按
`亮度 < 340` 取连通域、填洞，再按 `X = 388.6 + x·0.852` 映射回 1280 画布，作为
`footwear` 层塞回 `layers.json`。

**坑三：关节枢轴——复用和自动测量都不对，要用"自洽"的那组。**
`cut_at` 找的是"层内最窄行"，而这个层被裙摆切掉了大腿，于是膝落在小腿肚（1018，真实约 843）。
`--reuse-pivots` 看着能救，其实更糟：它只覆盖**输出的枢轴值**，`split_joint` 仍按测量值切分，
结果小腿在 1018 被切开、却绕 843 旋转，页面上是一道水平断裂。
**结论：枢轴与切分点必须来自同一次测量。** 自动测量偏低是"可接受的解剖误差"，
不自洽是"腿断成两截"，两者不是一个量级。`--reuse-pivots` 保留在脚本里，但只在
"新皮肤的服装没有改变轮廓"时才是对的。

**坑四：抠图留下两样东西。** 一是**腿部深色补丁**（生成图的错误阴影，位置偏高、边缘锐利，
在深色背景上像贴了两块胶布）；二是**边缘白边**（泛洪抠图后，半透明像素的 RGB 仍是白底，
124px 显示时是一条亮线贯穿手臂）。两者都在原始层上修，修完再导出：

```python
# 补丁：向肤色中位数插值 75%，保留一点形状
soft = gaussian_filter(mask.astype(float), 3); soft = clip(soft * 1.6, 0, 1)[..., None]
rgb = rgb * (1 - 0.75 * soft) + skin_median * (0.75 * soft)

# 白边：每个半透明像素借用最近的不透明像素的颜色（alpha 不动）
ind = distance_transform_edt(~opaque, return_distances=False, return_indices=True)
rgb[edge] = rgb[ind[0], ind[1]][edge]
```

**还有一处不是像素问题，是布局问题：`device lock` 压在了裙子上。**
它是 z-index 8 的半透明浅色板，在战斗服上正好落在白色髋甲里，谁也看不出来；
同一位置在蓝裙上就是裙摆中部，一块浅色四翼形状读作"裙子破了个洞"。
锁扣的位置因此进了 `LaciaSkin`（`lock`），蓝裙把它挪到腰带（y 388）。

### 6.2 接入：一个 `LaciaSkin` 装下全部差异

```ts
export interface LaciaSkin {
  base: string;                    // 位图目录
  parts: readonly LaciaPart[];     // 30 层坐标
  knee / elbow / wrist / ankle;    // 关节（身体属性）
  bone?: Record<string, LaciaBone>;// 新层名 → 骨骼（bottomwear → torso）
  components?: readonly string[];  // 这套衣服挂哪些可选组件（蓝裙 = []）
  lock?: readonly [number, number];// 只在挂了 lock 组件时才用到
}
export const LACIA_SKINS = { suit, dress, haru, sora, chibi } as const;
```

`rig.ts` 里 `PIVOT` 拆成 `FIXED_PIVOT`（跨皮肤通用）+ `pivotTable(skin)`；
`ARM_CHAIN` 变成 `armChain(skin)`；类里存 `this.pivot` / `this.limbs`。

**五官变体只在"同一个人的两套衣服"之间共享**：蓝裙和战斗服是同一张脸，眉位差 (2,1)、
嘴位差 (1,1)，在 9px 的显示尺寸下不可见，所以两套共用那 14 个文件。三个原创角色各自
有 `faceBase`（`/lacia-rig/haru/` 等），因为它们本来就是三张不同的脸。判断标准是
"换了之后还是不是同一个人"，不是"换了之后是不是同一套骨架"。

### 6.3 可选组件与动作模组（为什么不是 N×N 可见性表）

用户的要求原话：**"其他服装是没有武器的，应该把组件做成可选，每个组件带一套动作模组，
动作要能设置其他组件的显示"**。最后他自己也对 N×N 矩阵存疑，让先调研再定。

调研结论与引擎通行做法一致：**按身体部位寻址（Unity 的 AvatarMask、蒙皮骨骼遮罩），
可见性用稀疏的、有时长的通知（UE 的 AnimNotifyState），而不是一张稠密的布尔表。**

#### 结论

三条一起用：

1. **动作对「槽位」广播，不对「组件实例」。** 列数是身体部位的个数（13），不是组件的个数。
   一条 `aura: false` 的规则对现在和将来所有 aura 类组件都成立。
2. **缺省可见，只写要隐藏的。** 动作的 `visibility` 是稀疏的 `Partial<Record<Slot, boolean>>`。
   角色自带的模组不写这个字段 —— 这就是"默认其他组件都显示"，不需要额外声明。
3. **两个方向各写一半。** 动作说"我播放时这个槽位让开"；组件说"我遇到这些动作自己让开"
   （`hideIn`，可以写动作 id，也可以写 owner 当标签用）。解析顺序：**动作显式 > 组件自声明 > 可见**。

#### 为什么不做那张 N×N 表

| | 稠密表 | 稀疏双向 |
|---|---|---|
| 要写的格子 | 动作数 × 组件数（实测规则只占 5/30） | 5 个条目 |
| 加一个组件 | 改**每一行**动作 | 只改新组件一个文件 |
| 表达"后半段才隐藏" | 不行，格子是快照 | 行，动作有时长 |
| 真相份数 | 2（动作 + 表，会漂） | 1 |

最关键的是第二行：用户要的"一键加入"和稠密表在结构上矛盾 —— 表要求每个新组件回头去改所有
已有动作，而"新组件自己声明可见性"恰恰是"改一个文件"。二者只能选一个。

**矩阵没有取消，只是从"写"变成"算"。** `visibilityMatrix()` 从上面两半稀疏声明推导出来，
给设置面板看、给 `verify/components.mjs` 断言。它没有独立存在，所以不可能和规则漂移。

#### 数据结构

```ts
type MascotSlot = 'head'|'face'|'neck'|'torso'|'back'|'waist'|'arm'|'hand'
                |'leg'|'foot'|'weapon'|'aura'|'device';

interface MascotAction<H> {            // H 是渲染器给的把手
  id: string;                          // 'monolith:unfold' / 'svg:held' / 'self:poke'
  owner: string;                       // 组件 id，或 'self'
  visibility?: Partial<Record<MascotSlot, boolean>>;  // 稀疏行，缺省可见
  duration?: number;                   // ms，0 = 保持到被下一个动作替换
  onStart?: (h: H) => void;
  onEnd?: (h: H) => void;
}

interface MascotComponent<H, S> {      // S 是渲染器的主体（皮肤 / 造型配色）
  id: string;
  slot: MascotSlot;
  parts: (ctx: { uid: string; subject: S }) => { mount: MascotMount; html: string }[];
  actions?: MascotAction<H>[];
  hideIn?: readonly string[];          // 动作 id 或 owner 标签
  fits?: readonly string[];            // 只属于哪个角色，省略 = 都能挂
}
```

动作只能通过 `RigHandle` 碰骨架（`impulse` / `kick` / `setDeviceForm` / `say` / `after`），
拿不到 rig 本身。`after` 由 rig 持有，动作被打断时它的延迟回调一并清掉 —— 否则 `railgun`
那个 260ms 的甩头会在你已经切到别的动作之后再打一次。

#### 运行时开销

- 解析只在**动作开始和结束**各做一次，`O(组件数)` 次属性写。帧循环零成本，没有新分配。
- 隐藏用 `visibility:hidden` + `opacity:0`（不是 `display:none`）：子树不绘制，但 DOM 和
  已解码的位图、SVG 渐变 defs 都还在，重新显示只花一次属性写。`visibility` 的过渡延迟
  0.24s 让不透明度先走完，否则第一帧就闪没。
- 矩阵不进运行时。

#### 加一个组件

写一个对象、注册进 `LACIA_COMPONENTS`、在皮肤的 `components` 里列上。不用碰任何已有动作。
现在只有两件：`monolith`（槽位 `device`，挂 `stage`，带四个形态动作）和 `lock`
（槽位 `waist`，挂 `hips`）。蓝裙两件都不挂，所以它没有武器、没有锁扣、没有装置控制台 ——
这句话写在 `SKIN_COMPONENT_DEFAULTS.dress = []` 一行里，引擎里没有任何地方判断"是哪套衣服"。

#### 一个跨组件的规则，和它的代价

`monolith:unfold` 声明 `visibility: { waist: false }`：八片晶体板锁出铰座时，锁扣的四片
压板是那个铰座的固定件，让开 1.6 秒再回来。这是目前唯一一条跨组件规则，也是唯一需要
解释的取舍 —— 动作结束时全槽位自动恢复，所以它不需要在别处写一条配对的"显示"。

### 6.4 三个原创角色不是"三套衣服"，是三副骨架

小春 / 小晴 / Q 版最初是手写的内联 SVG（`src/lib/mascot/svg.ts`）。那条路已经判死，
理由写在 `docs/mascot-motion-research.md` §5.2：**手调贝塞尔画不出生成模型的量级**，
怎么调路径都追不上，用户的原话是「还是丑」。现在四个角色走同一条流水线（§6.6），
差别只剩数据。

接进来时踩到的第一个坑是**把它们当成第三套皮肤**。蓝裙确实只是"换一组图层 + 换一组
枢轴"，因为她和战斗服是同一个人、同一张画布、同一套表情。小春不是——她 328×1277，
髋在 (167.5, 543)，脸的形状不一样，表情变体是另一批文件。把这三种差异写进引擎的
`if (skin === 'haru')` 就回到了"每加一个角色改一次引擎"。

所以 `LaciaSkin` 加了四个字段，**让引擎按数据分支**：

```ts
export interface LaciaSkin {
  base: string;                     // 位图目录
  parts: readonly LaciaPart[];      // 图层坐标（脚本生成，勿手改）
  knee / elbow / wrist / ankle;     // 关节
  bone?: Record<string, LaciaBone>; // 新层名 → 骨骼（bottomwear → torso）
  components?: readonly string[];   // 这套皮肤挂哪些可选组件
  lock?: readonly [number, number]; // 只在挂了 lock 组件时才用到
  /* ↓ 这三条是为了"另一个角色"，不是为了"另一件衣服" */
  canvas?: readonly [number, number]; // 画布尺寸（CSS 变量 --lr-cw/--lr-ch）
  frame?: Readonly<Record<string, readonly [number, number]>>; // 十三根非关节枢轴
  faceBase?: string;                // 表情变体目录（/lacia-rig/haru/）
  noOverride?: boolean;             // 拒绝调用方传进来的组件列表
}
```

三个具体后果，每一条都是踩过才知道的：

- **变换原点必须取她自己的 root 枢轴，不是画布中心。** 蕾西亚的 root 在 x=246、画布宽
  493，两个数碰巧都接近中线，所以"绕中心转"一直没暴露问题。小春的髋在 x=167.5 / 宽 328
  ——绕画布中心转会把她的脚甩起来。
- **`--lr-k`（1 / 画布高）必须预计算成字面量。** CSS 里 `calc()` 不能用 `var()` 做除数，
  所以 `canvasCss(skin)` 输出 `--lr-k: 0.000784` 这样的八位小数，`--lr-s` 再乘它。
- **`noOverride` 是必要的。** 后台的"挂载组件"列表对非蕾西亚角色是空的，但如果调用方
  还留着上一次存的 `['monolith','lock']`（切角色时没清），引擎会照着 id 去找组件——
  找不到是幸运，找到了就是给 Q 版挂上秘棺。

`skinComponents()` 因此多了一道守卫：

```ts
export function skinComponents(skin: LaciaSkinId, override?: readonly string[]) {
  const s = LACIA_SKINS[skin];
  return resolveComponents((s.noOverride ? s.components : (override ?? s.components)) ?? []);
}
```

### 6.5 十三根枢轴是量出来的，不是写死的

`FIXED_PIVOT` 里那十三根（髋 / 胸 / 脖 / 头 / 两肩 / 两膝 / 两肘 / 两踝 / 两腕之外的）
原本是照 1276 px 高的蕾西亚手写的常量。换角色之后全部改成 `export_assets.py` 从图层
包围盒推出来：

| 枢轴 | 怎么来的 |
|---|---|
| `hips` / `chest` | 髋是 `legwear` 的顶边中点；胸是髋上 `40 * k` |
| `neck` | 脸的下缘下方 `24 * k`（**没有脖子层时退回脸的水平中心**） |
| `head` | 脸的下缘下方 `4 * k` |
| `shoulderL/R` | `armwear` 顶边的内外两侧，各让 `30 * k` |
| `knee` | 在 `legwear-{side}-up` 的窗口内找"最窄行" |
| `elbow` | 在 `armwear-{side}-up` 的窗口内找"最窄行" |
| `wrist` / `ankle` | 对应层的底边中心 |

`k = 画布高 / 1276`。**这些绝对偏移必须跟着画布缩放**：Q 版画布只有 816，头占了一半，
"髋上 40 px" 会落进下巴里。

`joints.cjs` 的判据也跟着变了：它读的是骨头的变换矩阵，**没有部件的骨头上也照样报出
行程**（Q 版的 `legR` 上根本没有图，却报了 1.97°）。现在它统计每根骨头上 `img.lr-part`
的数量，`noPart` 里的关节只报告不判分。

### 6.6 重做一个角色的流水线

```bash
python docs/lacia-rig/pipeline/gen_char.py     --ref lacia_idle.png --prompt "..." --seed N   # 1. 出图
python docs/lacia-rig/pipeline/prep_source.py  --in out.png --out docs/seethrough-<x>/source.png  # 2. 抠图 + 对齐
python docs/lacia-rig/pipeline/run_st.py       --in source.png --out layers/                  # 3. See-through 拆层
python docs/lacia-rig/export_assets.py --layers layers --name <x> --source source.png  # 4. 导出
python docs/lacia-rig/gen_face_variants.py --src source.png --out public/lacia-rig/<x>/  # 5. 表情
```

每一步的坑：

1. **必须 img2img，不能 txt2img。** 骨架要求站立 A-pose，`cut_at` 在固定窗口里找"层内
   最窄行"来测肘和膝；手臂横过髋部就落到窗口外，量出来的关节是错的。拿 `lacia_idle.png`
   当结构输入是最省事的姿势锁定。
2. **抠图是四边 flood fill，不是按颜色阈值。** 生成图背景是纯黑，但发梢/描边也有近黑
   像素；从四边灌水只吃掉"与边缘连通"的那部分。
3. **兜帽是拆层流水线的天敌。** 小晴前两版是连帽雨衣，See-through 把两只袖子和帽兜塞进
   同一个 `handwear` 层——兜帽布料和袖子物理相连，按连通域永远切不开。这是**设计约束**，
   不是服装偏好：改成立领之后同一个拆层器干净吐出两只手。改角色设计前先想清楚
   "拆层器能不能切开"。
4. **孤层要回收。** 拆层会静默丢细条（小晴的侧辫 182×70、3105 px，在任何图层里都不存在）。
   解法是减法而不是重画：源图里有、而所有图层都没有的像素，按定义就是丢的那块。
   判据是"有没有内部"——`binary_erosion(iterations=3)` 之后还剩核心的才算真物体。
   腐蚀一次时 Q 版会"回收"出 207×788 的碎片，那全是 5 px 描边和 1 px 配准差。
5. **Q 版的骨架是部分为真的。** 大腿贴合 → 拆层找不到两条腿 → 没有膝盖可测。
   `export_assets.py` 把膝盖钉在髋上（`KNEES["r"] = FRAME["legR"]`），而不是在没有收窄的
   形状上按 45% 猜——后者正是 `JOINT_BANDS` 那套搜索窗口存在的理由。

**已知缺口**：`docs/seethrough-haru/` 归档了 46 个图层，小晴和 Q 版的图层在导出后没有
留档（只留了 `source.png`）。要重新导出这两个角色必须重跑第 3 步（各约 5 分钟 GPU）。

### 6.7 加载：把"参数"留在服务端

看板娘的体积分三块，处理方式不同：

- **标记（HTML）**：四个角色都是**服务端按参数生成**——角色、皮肤、组件列表是渲染参数，
  浏览器收到的是结果。换角色换皮肤不增加任何下载，只换 HTML 里那一段。`parts-*.ts`
  那几份坐标表（各 0.12–0.14 MB）因此完全不进浏览器，只有 Node 侧读。
- **引擎（JS）**：骨架引擎 11 KB(gz) 只在真的渲染骨架时才有 `<astro-island>` 标记；
  再加上 `client:media="(min-width: 901px)"`，手机（CSS 本来就把看板娘隐藏了）连 chunk
  都不下载。
- **按需模块**：素材包的位移场（`mascot-warp.ts`，3 KB gz）只有包才用得到，改成
  动态 `import()`；内置角色页面不再为它付费。

拆包时踩过的两条：

1. **`index.ts` 只能给服务端和后台用。** 客户端要什么就 import 那个具体模块（`./meta`、
   `./lines`），从 `index.ts` 进来会把整个角色表拖下水，等于白拆。
2. **手绘造型删掉之后，后台 chunk 少了 6.5 KB(gz)。** 那套几何（565 行路径 + 四个
   `Look` 配色对象）只为了在设置面板里画 84px 的预览，而四个角色都有 `thumb.webp`。
  现在全站客户端 JS 合计 158 KB(gz)，比删之前少 9 KB。

## 7. 已知取舍

- 上下身没有分开：`topwear` 在拆层里是整块装甲，腰部分不开，所以「弯腰」这类动作做不了，
  只有重心位移 + 脊椎微转。
- `device lock` 与腰带翼板合成一个视觉单元（见 §3）。
- 展示页 `--lr-u` 按视口高度分三档（440 / 500 / 580），没有做连续缩放：
  连续缩放需要 JS 量尺寸，而骨架是服务端渲染的，不想为了 20px 引入一次测量。
- **看板娘形态下，装置只能用鼠标点**。整个立绘包在 `.mascot-btn`（一个 `<button>`）里，
  拖动、点击、键盘聚焦都依赖它；把装置再做成 `role="button"` 就是 `<button>` 套
  `<button>`，是无效嵌套，浏览器也不会让它拿到焦点。所以键盘用户切形态的入口是
  `/lacia` 那四个真按钮（Tab 可达，`aria-pressed` 跟着走），看板娘这边只有鼠标/触摸。
- **单栏布局让页面变长**：画板 870px 高（人物 560 + 上下各 0.22×560 的扇面余量），
  面板再占 ~360px。这是 1:1 的直接代价——两栏时画板只有 750px 宽，装不下 1.9 倍身高的扇面。
  台词卡不再需要固定高度（人物在面板上方，长台词推不动她），出处行仍截两行。
- **1:1 到 760px 为止**：画板出血到 `min(100vw − 48px, 1440px)` 之后，760px 以上装置都是 1:1；
  再窄只能缩（0.82 / 0.66），因为 1:1 会让**人物**只剩 250px 宽（见 §3.5 表）。
  这是布局约束，不是美术选择。
- **表情是"位图换形 + 少量位移"**：眉 3 形、嘴 4 形，全部烤好；弹簧只做几个像素的游走。
  口型是**音节级**（无音频，汉字无读音）、泛红只有 on/off（见 §3.4）。
- **障壁会挡脸**：障壁态装置 `z-index` 抬到 2 画在她前面，最初蜂窝盖到了下巴以上，脸被糊住。
  现已把整簇下移到下巴以下（`hub−500`），只覆盖躯干。**这一态永远不要覆盖到 y<200。**
- 看板娘的装置按 0.66 / 0.82 / 1 三档画，且因为绕枢轴缩放会贴近她身体（见 §3.5）。
- **角落看板娘抬了 14px**（`.mascot[data-kind='rig'] { bottom: 14px }`）。立绘的鞋底在
  画布 y=1274/1276，`bottom: 0` 时离视口下缘不到 1px，读作"被切掉"；而膝骨绕踝附近的
  枢轴转，靴子本身还会摆到装置盒子下方约 6px（`overflow: visible` 下不受盒子约束）。
  14px 是 4 秒采样所有骨头 `getBoundingClientRect().bottom` 取最大值算出来的，
  整个弹簧周期净空 ≥8px。另有 `max-height: 520/420px` 两档降到 260/200。

### 已经验过的事（别再重复怀疑）

- `/lacia` 上不会出现第二个蕾西亚：`PublicLayout` 有 `noMascot` 开关，页面直接不渲染

- **`<svg>` 根元素不能接事件**。它是 replaced element，`pointer-events: auto` 会占满
  整个 3000 单位盒子，把周围所有点击都吞掉——表现就是「点她身体却在切形态」。
  正确做法：根元素 `none`，只给当前形态的组 `auto`（见 `lacia-rig.css` 那段注释）。
  展开态只开放枢轴环与镜头，否则扇面铺满她全身，她就点不着了。
- 点击分流实测：点棺体 → `railgun` + 装置读数；点她身体 → 台词变、形态不变。

- **两处修过的坑**：`mouthOpen` / `mouthWide` 的弹簧初值原本是 0，而它们的静止值是 1，

  过冲 **8.8°（5.8%）**后锁死；导轨态远侧半壳位移 `0 → 161(550ms) → 152(900ms)`，
  过冲 9 单位；障壁态六边形缩放 `0.12 → 1`，过冲 5%。

- **缓动的真相**：`cubic-bezier(0.34, 1.06, 0.4, 1)` **不产生过冲**。直觉上"控制点 y 超过 1
  就是过冲"，但后两个控制点也在 y=1，曲线被拽回来，峰值只有 1.0006。
  第一版注释写着"过冲约 6%"，逐帧轨迹是干净的 ease-out。要真的过冲，第一个控制点的 y
  得拉到 1.4 附近（`cubic-bezier(0.34, 1.42, 0.52, 1)` 峰值 1.058）。

- **联动实测**（`docs/lacia-rig/verify/linkage.cjs`，连跑三次退出码 0）：见 §3.2.1。
  这个脚本有三个不显眼的前提，缺一个就会"假绿"或"假红"：
  ① 页面开着 `autoForms`，每 6–8s 自动切形态，待机时的"运动幅度"可能是切形态而不是待机，
  所以控制组要验 `form0 === form1`，不干净就重采；

  逐帧变化率是 0.9 对 0.06，差 8 倍。
