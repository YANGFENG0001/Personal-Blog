# 架构与设计决策

## D1：SSR + 数据库，不用纯静态 + Git

需求里同时有这几项：

- 在线编辑和即时发布
- 私有草稿、任务和学习记录
- 可动态切换的分站、栏目、文章权限

纯静态构建要么有发布延迟，要么容易把私有数据打进构建产物。因此选择 Astro **SSR**（output: server）：每个请求都在服务端按权限查询，发布和撤回立即生效。

公开页面几乎不发 JS，性能接近静态站。

## D2：SQLite 而非 Postgres、D1 或 R2

目标是“个人长期运行、维护成本合理”：

- 单个文件，备份就是复制。
- WAL 模式下并发读完全够用。
- 不需要额外的数据库服务。

数据访问集中在 `src/server/services/*`，使用纯 SQL，以后要迁移到 Postgres 也只需改这一层。

## D3：没有采用 Starlight / starlight-blog

Starlight 是静态文档框架，内容来自仓库里的 Markdown 文件。本项目的内容存放在带权限的数据库中，用 Starlight 会出现两套内容源，私有内容也更容易漏进构建产物。

知识库因此改为数据库中的层级节点，节点关联文章，通过 `/knowledge` 公开展示，展示时同样经过权限判断。

Markdown 的可迁移性由“导出全部为 Markdown + front matter”来保证。

## D4：唯一的公开判定

`src/server/visibility.ts` 中的 `PUBLIC_POST_SQL` 是唯一的公开判定条件：

```
published ∧ post 公开 ∧ 栏目公开 ∧ 分站公开 ∧ published_at ≤ now
```

首页、分站、栏目、文章、搜索、标签、归档、RSS、sitemap、知识库和公开统计都只通过这个条件查询。

返回给公开页面的文章对象会经过 `redactForPublic` 处理：去掉 Markdown 源码，未公开的心得和进度会被置空。

## D5：认证

- 只有一个站主账号，由命令行创建，网页上没有注册入口。
- 密码用 argon2id 哈希（Node 内置；旧版 Node 回退到 scrypt）。
- 会话 token 存在 HttpOnly 的 SameSite=Lax cookie 中，数据库里只保存它的 SHA-256。
- “记住我”是 30 天滚动续期；不勾选时为 12 小时，并且是浏览器会话 cookie。
- 所有修改操作都要求 Origin 与站点一致，并携带会话绑定的 CSRF token（请求头 `x-csrf-token`）。
- 登录失败限速：同一 IP 或同一用户名 15 分钟内最多 5 次，记录持久化在 SQLite 中。

## D6：CSP

Astro 的 `security.csp` 会为每个页面计算内联脚本和样式的哈希，生成严格的 `script-src`。中间件再补充 `frame-ancestors 'none'`。

Shiki 和 KaTeX 需要内联 `style` 属性，因此只放开了 `style-src-attr 'unsafe-inline'`，脚本仍然完全受哈希约束。

## D7：游客预览

悬浮球只会在服务端确认存在站主会话时才渲染。

站主访问公开页面时，走的是与游客**完全相同的查询**；会话只决定是否显示悬浮球，不会带来任何额外的数据访问。因此游客预览一定准确。

## D8：统计口径

| 指标 | 计算方式 |
| --- | --- |
| 建站天数 | 设定的起始日到今天，包含当天 |
| 发布天数 | 当前公开文章的首次发布日期去重计数，不等于文章篇数 |
| 连续发布、连续学习 | 截至今天的连续天数；如果今天还没有记录，就从昨天往前数，所以不会在当天早上就“断签” |
| 连续在线 | 连续每天都有心跳（服务自身每 5 分钟写一次，或外部监控调用 `/api/heartbeat`）的天数；当天必须有记录 |
| 连续学习的数据来源 | 保存文章、完成任务、手动打卡，这些都只记录在私有的 activity 表中 |

只有站主在后台同时勾选了“启用”和“公开”的统计，才会在公开页面中计算并输出。

## D9：鼓励概率机制

纯函数实现，见 `src/lib/encourage.ts`，单元测试覆盖。

规则：每隔 interval 判定一次。没有触发时，概率加上增量，最高到上限；触发时，概率重置为初始值并进入冷却。状态保存在 sessionStorage 中，标签页处于后台或用户正在输入时跳过判定。

## D10：原型的处理

`框架/` 中的 V4 原型只作为视觉和交互参考，代码没有沿用。原型存在的问题包括：

- 前端假登录
- 私密文章写在公开的 JS 中
- 数据存放在 localStorage

保留下来的部分：配色和排版变量、左侧轮盘、顶部栏目条、头像卡片、相关链接替换侧栏、悬浮球、鼓励提示的交互形态。
